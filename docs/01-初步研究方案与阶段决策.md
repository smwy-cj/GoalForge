# GoalForge 初步研究方案与阶段决策

整理日期：2026-10-15。

本文件根据前期已确认的研究方向重建方案摘要。旧版细分方案和Skill草稿已按清理要求删除，当前记录用于固定阶段边界与后续工作顺序，不代表原文件逐字恢复，也不代表相关能力已经实现。

## 1. 研究目标与推进顺序

先逐步验证Skill对目标提取和目标模型构建的帮助，再搭建Agent并检验其编排价值。前期遵循论文的大致框架；目标追溯、模型验证和修复均纳入Skill与Agent的实现目标，不单独设置S3阶段。

论文依据为 Generative Goal Modeling，参考[论文](https://arxiv.org/abs/2509.01048)及[作者仓库](https://github.com/cmu-relab/goalgeneration)。基本追溯与图检查和本项目拟扩展的结构化语义问题、局部修复、版本审计应分别报告，不能把所有能力都称为超出论文范围的创新。

## 2. S1：Skill实现与逐项验证

先建立统一输入、目标、证据、关系、问题与版本记录，再实现可单独运行的能力。

| Skill | 预期职责 |
|---|---|
| goal-extraction | 从源文提取目标候选，区分动作、障碍和偏好，保存来源 |
| goal-tracing | 定位精确引文并判断源文支持程度，区分直接表达与推断 |
| goal-normalization | 统一目标表达、处理重复和粒度，保存合并或拆分映射 |
| goal-refinement | 判断精化、相关或等价关系，保留不确定判断及理由 |
| model-validation | 检查引用、重复、自环与有向环，并记录语义疑点 |
| model-repair | 针对问题提出局部补丁，复检结果并记录版本变化 |

S1先验证单项能力，再比较固定流程中的组合效果。使用相同模型、输入和可比预算，区分基础提示、Skill辅助及移除某项能力的消融设置。具体模型、提示、采样参数与重复次数应在实际实验前固定，不能由本次数据整理替代实验。

预期产物包括目标清单、目标关系图、证据追溯表、验证报告、补丁及版本记录、可复查的运行记录与人工评测结果。JSON作为机器数据，Markdown图与说明用于检查；这属于工程适配，不直接等同论文的严格复现。

## 3. S2：Agent集成与验证

在S1能力能够独立执行并有可比结果后，再加入Agent编排。Agent复用同一套Skill和数据契约，负责任务路由、有限重试、修复闭环、断点恢复及人工决定记录。

集成评测比较固定Skill流程与Agent流程，并记录成功率、目标与关系质量、证据支持、实际调用及成本。Agent编排的增益与各Skill本身的增益分别讨论；结构检查通过不等于模型语义正确，生成修复建议不等于修复成功。

## 4. 数据与评测口径

本阶段最终采用34份固定版本访谈，已形成3篇开发参考与31篇储备语料。数据规模、标注来源和质量检查以[最终采用数据集说明](12-最终采用数据集说明.md)为准。

- 开发参考用于确定粒度、证据和关系口径；不作为未经接触的独立盲测。
- 显式目标、源文推断目标和人工设计扩展分别记录与评测。
- 人审关系、助手处理关系和不确定项分开报告，不混成统一人工Gold。
- 真实系统错误应来自实际模型运行并经审核；受控注入错误单列，不用人工标注分歧替代自然错误。
- 同一源文的轮次、翻译及派生产物跟随文档划分，避免跨集合泄漏。

## 5. 当前完成范围与下一步

已完成：研究阶段与六类能力分工确定、主数据源固定、34篇源文处理、3篇开发目标与关系整理、最终数据说明及文件哈希记录。

尚未完成：可运行的Skill Adapter与Runner、正式模型对照实验、Agent实现、独立测试标注及真实系统错误修复集。

下一步从S1的提取与追溯开始，建立最小可复查的运行流程；在真实运行输出上逐步加入规范化、关系构建、验证与修复，再依据单项结果决定S2集成。
