# KAOS 目标建模与交付

把有依据的目标组织成清楚的有向无环图，让用户直接审核。采用 KAOS 概念层核心子集，不宣称完整形式化实现；缺候选时先交 goal-extraction。

## 建模

- 先按[联系发现](references/relation-discovery.md)保存具体化、实现方式、贡献和过程先后的有向联系及判断状态，再按[精化规则](references/modeling-rules.md)核验共同充分的子目标组与完整替代方案。两阶段分别记录原句、条件、理由和假设。
- 不将相关、相似或操作先后当作精化；按上下文判断整组，不默认穷举两两关系。
- 不强造根目标或固定层数；允许多根、孤立与共享目标。未确认或不完整组保留问题，不绘成成立层级。
- 目标简短但不丢主体、否定、条件、时间和数量；主体与责任不擅自等同，未知不编造。
- 保留提取交接的“一目标一核心动作”粒度和稳定 ID，状态等目标按[目标边界](../goal-extraction/references/goal-boundaries.md)保留；主题概述只用于阅读，不能再次压缩或合并节点。发现复合目标须回到提取拆分与核验，动作先后不自动成为精化。提取覆盖记录由提取/复核工具审计，当前组装器不读取它，不能据其检查通过升级目标支持。
- 先组织目标、提出精化候选，再整组核验并以正常/异常场景检查。新增、拆合或实质改写目标须回到 goal-extraction 修订并核验，可由同一助手连续执行。
- 贡献、实现方式等只进入v2定义的独立relations层，不自动成为成立精化。障碍、偏好、冲突和责任仍按现有字段及问题保留，不能伪装成四种联系之一；语义资格沿用[目标边界](../goal-extraction/references/goal-boundaries.md)。

## 工具与交付

[模型契约](references/output-contract.md)定义唯一机器结构，[工具说明](references/tools.md)定义 template、assemble、inspect、finalize、feedback 与本地预览命令。使用实际判断与原文执行，不手填检查通过。

默认 HTML 为有向无环目标图，每目标一个节点、精化组一个连接点，共享目标只画一次。另有目标清单与目标联系视图；联系逐项标明类型、方向、状态和证据，单独审核及导出。精化图箭头只表示层级展开。

新任务默认使用goalforge-kaos-2，旧v1继续读取。升级必须明确执行upgrade-template与assemble --migrate-from并重新编制判断，不从旧关系猜新类型。修订按依赖要求重评，不只替换文件哈希。

交付 HTML、JSON、短 MD 与必要附件，SVG 按需取出。来源、判断、版本及检查绑定同一模型。保存提供实际回执或清楚说明仅发起下载，同时支持复制与完整文本。

## 修订

真实反馈按[修订规范](references/reassessment.md)生成受影响目标和组待办。助手回查原文，重新编制必要判断，再以父模型与反馈重建副本、复检、交付。未解决意见继续保留，人工状态保持待审，不从分项意见推断完整认可。
