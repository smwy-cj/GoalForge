## 生成与复核隔离

用户明确授权独立子代理。baseline 和 revised 使用两个不继承父对话内容的生成上下文；二者只见各自版本技能与三篇原文，不看对方答案、历史 output、评审报告或带答案的参考资料。两分支使用相同的中性任务描述与继承模型配置；实际模型标识、采样参数、token 消耗或预算无法从执行信息取得时记录 unknown，不虚构完全受控条件。

独立上下文复核者先只读源文，记录检查范围与语义不变量；两个分支结果冻结后才读取结果。它与生成方共享模型体系，属于独立上下文模型复核，不能称为独立人审、外部验证或形式证明。生成方自检另存，不充当此项。

## 比较方法

逐篇对齐语义相近的目标，不按 ID 或数量强行一对一匹配。保留一对多、缺项、合并和无法判断。记录对象、原文轮次/引文、两种表述、成立条件、判断理由、类别与处理状态。

分别列出：

1. 已证实的表述偏差（范围、强度、主体、条件、选定方式）。
2. 来源与推断问题（信念变事实、现状变要求、缺失正面推断依据）。
3. 表达不足（含义基本忠实但必要关系/状态不清）。
4. 候选遗漏风险与经上下文确认的遗漏；二者不混合。
5. 有效目标覆盖、正确/边界案例的保留情况。
6. 全部精化组的充分性、方案完整性、条件、假设和反例；无精化也可以是合理结果。
7. 未决问题与可能退化，以及工程核验结果。

一个对象可有多个问题，问题条目数不能当错误目标数；不合成任意加权分数。三篇是已接触开发案例，不能外推总体错误率。扩展篇若只有生成方自检，要明确区分复核覆盖。

## 扩展门槛和修订

- 完整源文与引用位置可验证；工程检查真实执行并绑定实际文件。
- revised 试运行没有尚未处置的严重无依据强化、信念升级或错误成立精化。
- 正确意图/例外没有为消除问题而被删除。需要补充资料的项允许保留未知。
- 发现问题时先保存原始 v1，再另存受影响目标/判断/模型的新版本。记录前后对应和原因，重新核验；不得覆盖 v1 或把助手评审伪装成用户反馈。
- 技能快照如确需修改，另立版本与运行说明，不悄悄改动既有对照组。
