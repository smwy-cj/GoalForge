# 目标模型

版本：v1。人工待审。

- 积极求职时职位发布即获更新，非积极求职时每周更新即可
  适用条件：本人对市场每日职位数量判断未经验证。
- 优先通过职业邮箱接收更新，手机通知也可但应避免复杂和塞满通知栏
  适用条件：过多无关通知曾使重要机会淹没，不要求禁用所有通知。
- 职位更新邮件简洁并含所需必要详情及直接申请按钮
  适用条件：必要详情字段未完整确定。
- 评估职位时了解角色适合程度、报酬、地点、公司声誉及员工对工作和技术栈的评价
  适用条件：关注具体工作、技术栈和能给团队的贡献；未给权重或工资阈值。
- 将职位详情按列表、卡片或表格等清晰组织，并区分描述与职责以方便定位阅读
  适用条件：本人抱怨长描述需反复滚动；不推断删除全部描述。
- 在个人档案保存角色、经历、技能、项目和可自定义关键词，以持续获得相关职位并减少重复设置
  适用条件：希望列表预先使用档案，而不是每次另加过滤器。
- 标记无兴趣或屏蔽的职位后，希望它们不再重复出现
- 职位列表应保持相关和更新，避免申请明显过时的职位
  适用条件：不愿继续使用不相关或陈旧列表；未给有效职位的统一截止年龄。
- 申请时自动带入已有资料以减少重复手填，同时允许针对某些职位修改内容
  适用条件：部分职位愿意定制；不要求完全禁止编辑。
- 在求职门户内保存和追踪感兴趣职位，方便稍后申请而无须另开笔记应用
  适用条件：本人不确定现有平台有无bookmark。
- 保持申请职位及个人求职数据私密，避免其他人知道申请方向或从外部平台来联系
  适用条件：谁可因申请而查看数据的精确授权边界未说明。
- 可以用AI发现匹配职位；AI代写申请内容须经本人核实且不能自动进行
  适用条件：AI识别职位受欢迎但未被明确宣称绝对必需；申请撰写自动化不被接受。
- 能追踪自己申请的状态和雇主的回应情况
- 希望收到申请反馈，以改进后续申请
- 通过发布职位的人建立联系并可能获取转介
  适用条件：对需要快速申请的情况，等对方再发链接不理想。
- 减少无关职位通知及陌生人的无关求职联系，避免重要机会被淹没
- 按本人最后的总结，理想职位更新应匹配个人条件并提供快捷申请入口
  适用条件：此处只表达最后总结的两个要素；时效、隐私、资料流转仍为独立要求。
  以下各项都需满足
    - 收到符合软件工程或机器学习方向、个人技能和资格条件的职位更新
      适用条件：考虑签证、经验和工作资格；本人提到约50%/60%技能匹配会考虑申请，语气含I think非固定统一门槛。
    - 希望可直接或在页面内申请职位，减少往返应用和公司门户的操作
      适用条件：页面内公司门户为认可方式；实际可实现性未核验。
