# 目标精化与图表达规范

## 语义

一个 AND 精化组表示：在明确领域假设下，该组子目标共同满足足以实现父目标。同一父目标多个完整组表示 OR 替代方案，每个方案内部仍全部满足。不能把主题相似、先后操作、有帮助或范围变窄直接当作这种充分关系。

先按[联系发现](relation-discovery.md)从原文识别类型明确的联系，再提出可能的精化组并核对整组，不穷举所有目标对。记录尚未确认的问题，未评估不等于无关系。

## 组织、核验与场景检查

先回答 Why（为何需要）、希望达到的状态、适用条件及 How（可能怎样实现），区分涉众目的、系统结果与实现策略。目标资格及强度统一沿用[目标边界](../../goal-extraction/references/goal-boundaries.md)，不在建模阶段重新定义。

提出精化候选后，在明确假设下检查 AND 整组的共同充分性；同一父目标的每个 OR 方案均单独满足完整性要求。部分贡献、主题相近、操作先后或“更喜欢某方案”不证明充分性。前提目标仍为 insufficient/contradicted 时，该组不得作为成立精化；未决范围尽量落到具体组。

以资料中的正常、异常场景检查触发条件、边界和可能反例。助手构造的场景须标为“分析假设”，不冒充访谈事实；说明场景检验的对象、发现的缺口和未知，不宣称穷尽或形式证明。有反例未解决时收回 supported/complete，保留 proposed/partial 与具体问题；不以补造目标修图。

新增、拆分、合并或实质改写目标时，返回 goal-extraction 保存版本与 ID 对应、重核当前语义支持，再重评受影响组。当前 candidate_id 直接作为 goal_id，保持一一对应；ID 对应不是新目标获支持的证据。

## 辅助关系与信息

- 障碍候选记录可能受阻的目标、发生情境和关系依据；不能确定端点时保留待关联问题。补救目标需另经提取核验。仅列障碍不等于完成风险分析。
- 偏好用于目标/方案取舍，保留适用条件和例外；更喜欢 A 不证明 A 足以满足父目标，也不证明 A 与 B 逻辑冲突。
- 贡献、冲突、操作化和责任与精化分开；负贡献不自动等于逻辑冲突，表达主体不自动等于实现责任方。不要把其他方法的关系全解释成 KAOS 精化。
- v2的relations只承接具体化、实现方式、贡献和过程先后；旧v1没有这一层。其他必要信息通过目标 conditions、依据与 questions/issues 承接，关键限制不只放在说明里。不能无损承接时记 limitations，不往 refinement_groups 塞入障碍、偏好或未定义关系；无记录也不表示已排除这些影响。

父目标、子目标、条件与推断均需依据。缺中间层不强补；可保留多根、独立目标或少量待确认建议。status=proposed 或 completeness=partial 作为问题保留，不展开成已成立层级。

目标主体、否定、范围、数字和时间保持一致；合并或拆分须保存映射，不因减少节点丢失要求。actor 仅记录来源主体，责任未知不分配。障碍关联到其影响的目标问题，不自动提升为已经证实的形式化障碍。

## DAG 表达

每目标一个节点，每个成立精化组一个连接点。边为“父目标→精化组→子目标”。图例明确箭头是展开方向，不表示执行顺序或因果；同一目标可由多个上层引用，仍只画一次。

连接点以“共同满足”或“方案 N”解释。组与目标均可点击查看依据并分别审核。暂不能建立层级时独立展示，不为追求一棵树造边。长标题允许视觉换行或省略，完整描述在节点提示及详情可读，省略不改变机器目标。

结构检查验证引用与无环，不能证明精化的充分性、完整性、可实现性。当前编制判断、独立语义审查、形式证明和人工意见分开报告。

精化图保持DAG；辅助联系按[联系发现](relation-discovery.md)分别核验循环，不统一套用精化DAG。成立组在v2需记录正常与异常场景检查及实际依赖联系，具体契约见[输出契约](output-contract.md)。障碍、偏好和取舍优先放在相关目标/组详情及问题中，不自行增加未定义图层。
