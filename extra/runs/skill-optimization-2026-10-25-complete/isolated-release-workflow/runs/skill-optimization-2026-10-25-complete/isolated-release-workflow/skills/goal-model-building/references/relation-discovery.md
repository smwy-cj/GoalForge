# 先发现联系，再核验精化组

先对每个目标明确主体、预期结果、范围、条件及其目的/方式；理由保持简短可核对。优先同一问答、共同场景、明确跨轮指代及孤立目标的相关上下文，不默认穷举所有目标对，也不把未评估判成无关系。

## 四种有向联系

| type | 起点 source_id → 终点 target_id | 不能据此声称 |
|---|---|---|
| specialization | 具体情境中的目标 → 一般目标 | 某个情境覆盖一般目标的全部适用范围 |
| operationalization | 实现方式/策略目标 → 所服务的目的 | 该方式在所有情况下均足以实现目的 |
| contribution | 有帮助的目标 → 受帮助的目标 | 帮助等于充分保证；负贡献自动是冲突 |
| precedes | 先发生的目标结果 → 后发生的目标结果 | 顺序等于因果或精化 |

端点只能引用已提取、核验的目标；原文仅有操作背景而无目标资格时，不为了画联系造节点。新发现的有依据上层目标先返回提取，记录推断及假设，重核后再建模；不固定补几个根。

每项记录条件、假设、关系原句、方向和简短理由。supported 表示编制者认为联系有依据，仍待人工审核；proposed 表示待确认；rejected 保留实际否定判断与依据。端点支持不足不能标 supported。没有评估过的目标对不补写 rejected。

判断基于两端目标的实际正文和条件，不能在rationale中把端点悄悄改成更宽的目的或补入未保留的方式。两种替代方法可能分别服务同一目的，但一种方法不因此实现另一种方法；缺共同目的目标时先回查提取或留问题，不为连边补根。后续标记、归档等动作可能帮助之后回访，不能仅因同属处理流程就反向认定它帮助此前识别。近同义重复应回提取整理，不能用贡献边掩盖重复。条件只写影响本判断的具体限制，不用“在原文情境内”等通用句遮住范围不一致。

具体化、实现方式和先后关系各自在非 rejected 子图中禁止循环；贡献可相互影响，不能一概套用精化DAG规则。方向有歧义时保留问题并重查，不能随意翻边消除循环。所有类型都不允许自环或重复同类型、同方向、同条件记录。

## 转入精化核验

只有实际声称子目标整组充分实现父目标时才编制 refinement_groups。按[建模规则](modeling-rules.md)检查共同充分性、替代完整性、范围及正常/异常场景；实际用作判断依据的联系在 relation_ids 中声明，不能省略依赖规避失效传播。

checks 保存 kind=normal/exception、origin=source/analysis_assumption、scenario、outcome=supports/counterexample/unknown、rationale。来自原文的场景另引用 evidence_ids。分析场景明确为假设，不冒充源文事实。supported+complete 组必须包含两类场景且无未解决反例/未知，所有依赖联系也须 supported；这些字段由作者判断，程序不能证明充分性。

发现不足就保留 proposed/partial 及具体缺口，不为增加边数扩写目标。普通联系始终单独展示，不转换成成立精化箭头；贡献或先后即使有依据也可能永远不形成精化组。

## 有界修复

结构失败后只修正定位到的引用、记录或经原文重新判断的对象，最多两轮局部修复（任务另有预算则按预算）；保存失败输入、报错、修改理由和实际次数。语义未知无新证据时停止该问题，继续其他对象。不能通过删除有依据目标、删除证据或任意改状态来凑通过；失败运行计入实验预算。
