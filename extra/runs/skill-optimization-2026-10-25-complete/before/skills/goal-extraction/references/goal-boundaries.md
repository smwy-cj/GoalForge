# 目标与关联信息的判断边界

本文件是内容边界的权威规则。字段以[目标契约](output-contract.md)为准，支持标签以[证据口径](evidence-rules.md)为准。示例均为泛化合成案例，不是评审答案。

## 从意图判断，按语义成分保留

目标需有达到、维持、避免或改善某状态的明确意图，或有正面依据支持合理推断。不要求出现“希望”等固定词；软目标、避免型目标和已实现能力的维持目标均可能有效。没有阈值时不编造阈值，不为画树补根。

同一段话可同时包含目标、障碍、偏好、事实和策略，必要时拆开并保留共同来源。只记录影响目标判断、取舍、精化或未决问题的信息，不恢复逐句分类清单。

| 内容 | 如何判断与保留 | 不允许的跨越 |
|---|---|---|
| 障碍候选 | 区分受阻目的、症状与补救方案；记录发生情境及可能受影响目标，不能确定端点时留待关联问题 | 抱怨直接当已证明障碍；问题取反当唯一补救方式 |
| 偏好 | 保留偏好对象、方向、情境和例外；同时有结果意图时保留目标；仅口味背景不自动造需求 | 更喜欢变必须，个人偏好变全体默认，编造比较对象、排名或权重 |
| 现有能力/事实 | 标明是受访者报告的现状；审查使用目的、继续维持或不可或缺的意图，再决定目标资格 | 现有能力自动成为明确要求；因为已实现就排除维持目标 |
| 信念/猜测 | 保存“认为、猜测、不确定”和所述后果，可据此保留顾虑与有依据的目标推断 | 把信念内容当已验证事实，架构猜测当唯一设计 |
| 动作/策略/方案 | 有结果意图时提取结果；原文选定的方式保留为约束，其他方式可作策略或候选方案 | 为抽象删掉已选方式；习惯升级为强制流程 |
| 提议 | 涉众提出期望时可保留候选与建议强度，采纳未知仍未知；分析者建议单独说明 | “可以考虑”变承诺；采访者提问未获回应就算涉众目标 |

障碍候选关联需说明依据；概念层分析不宣称已证明领域可发生性或阻碍条件。表达目标的人不自动承担实现责任，未知责任不随意分配给软件。

## 必须分开判断

- **origin**：explicit/inferred 回答意图是明确表达还是推断，不按关键词判断。
- **support**：核验当前整句是否受支持，不能用准确位置代替语义判断；与 origin 不必机械相等，差异需解释。
- **语气与强度**：保留“通常、建议、必须、更喜欢”以及可让步性；标题和 context 一起检查，不把例外藏进条件后强化标题。
- **采纳与审核**：默认 pending，真实分项反馈按版本保存；未提出反对不等于采纳。
- **优先与满足标准**：排名不等于必须/可选、精化或冲突；原文有指标则保留，没有则记未知。

## 候选整理与修订

1. 检查主体、结果、范围、条件、时间、强度和选定方式是否忠实。
2. 最终目标默认“一目标一核心动作及其预期结果”，按下文边界拆分复合目标，并逐项核验。明确与推断混合时优先拆分或保留分项依据，核心含义依赖推断时不能整体只用 direct 掩盖。
3. 合并前核对主体、情境和抽象层次；同义重复可合并，目的与手段不能只因文字近似就合并。
4. 支持不足时，仅在可修改模式下收窄/拆分并重核；仅核验模式保存原件与建议。保留旧文件、新旧 ID 对应、修改原因及未决问题；ID 不因排序改变。
5. 新提取的每个原始候选在[覆盖记录](coverage-contract.md)中保存去向及简短理由；重要原句另作逆向回查，无须给每句背景做分类。先检查已有覆盖，避免重复造节点。仅核验旧结果不虚构历史过程。
6. 阅读摘要与底层目标分开。概述可以简短，不能替代可独立满足的结果或丢掉涉众选定的实现方式；向量相似和出现频次不能单独决定合并或删除。

## 一目标一核心动作的边界

以一个核心动作及其预期结果组织最终目标；主体、对象、适用条件、语气、数量和时间限制随目标保留。“能完成其中一项而另一项仍未满足”有助于识别独立结果，但每项仍需原文意图依据，不能从动作出现推定目标资格。

| 表达关系 | 如何处理 |
|---|---|
| 多个独立动作 | 分别有意图依据、可独立满足时拆分，如“希望搜索航班、比较价格并预订机票”分别保留搜索、比较、预订目标 |
| 操作与直接结果 | “点击按钮以提交申请”通常保留提交目标；点击不自动独立。明确要求“一键提交”时，方式保留在目标中 |
| 前提与动作 | “获得授权后发送通知”中的授权保留为条件；除非另有意图依据，不从前提造目标 |
| 一个动作的多个限定 | “查找同时满足A与B条件的对象”仍可为一个查找目标；不能拆成两项后丢掉同一对象须同时满足的约束，也不能把AND改为OR |
| 替代方式 | “通过A或B完成提交”保留原有选择含义；不拆成必须同时采用A和B，方式本身的独立目标资格另判 |
| 单一状态、维持、避免或质量意图 | 保留该结果及原文指标，如保持资料可用、避免重复扣款；不为套动作句式虚构操作 |

共同条件传递到所有适用的拆分目标，局部条件仅绑定对应目标；否定、例外、建议强度和时间限制同样处理。目标可共享引文，但每个目标的完整语义都须单独核验，不能把复合候选的一次支持判断复制给全部拆分项。

有独立意图依据的目的与手段分别保留；原文明示的总体目的也可保留为上层目标，不为凑层级新增泛化摘要。独立动作的顺序或共同来源均不证明精化关系。语义无法确定的拆分保留具体问题，不靠动词计数、标点或目标数量定案。

## 少量边界例

| 合成材料 | 合理处理 |
|---|---|
| 可以接受凌晨出发，但更希望休息充分 | 保留休息目标和可让步偏好，不生成为禁止凌晨出发 |
| 不希望重要提醒被屏蔽，宁可多看到一些普通提醒 | 保留 Avoid 目标、误屏蔽障碍线索和取舍，不推出零误差 |
| 只报告断网时仍可阅读缓存内容 | 先保留现状；维持目标需另有意图或正面推断依据 |
| 没有某个现有功能就觉得产品不完整 | 审查维持意图及已有覆盖，不因已实现而过滤，也不重复造目标 |
| 抱怨小屏难操作，继而建议可以改善 | 保留改善候选和建议强度，不因含抱怨就机械判 inferred |

## 首轮记录边界

当前不定义或消费 `semantic-context.json`。跨阶段必要信息优先用 context、inference、evidence_candidates、review_questions 承接，关键限制必须保留在目标或条件中；无法无损表达时明确记交接限制，不宣称语义信息已完整传递。后续附件应先有唯一版本契约，再整体实现读写、源文/目标绑定、映射、依赖失效与展示，不能作为自由备注接入。
