# Codex 结果数据比对方案

日期：2026-10-22。目标是由 Codex 直接使用已生成结果、论文公开产物和原始访谈开展比较；无需先重跑整篇论文或等待完整人工标注。本文规定后续执行步骤，当前未完成 34 篇逐目标语义评分。

## 一、比较对象与当前证据

本地 output 中有 34 篇其他 agent 的运行产物，包含提取、追溯、关系判断、结构检查与最终模型。本次重新检查 final JSON 得到 398 个目标、342 条 related 边、5 条 refinement 边，schema_version 均为 goalforge-model-draft-1。现行 skill 使用的 KAOS 精化组另作新版，不能混为同一批。

数据来源已明确为 cmu-relab/goalgeneration，沿用本地固定提交 16c4ce8bed513bbfdada7ac900ba6b718617a6eb。本次已核验该提交的仓库文件树，确认 study1/data1 下存在 extracted-goals.json、sampled-goals.json、summarized.json、graphs.json、models.json、comps_final.csv 等文件。后续应补齐需要的文件并保存哈希，不需要重建访谈数据集，也不使用其他目录中的后续模型实验冒充原论文结果。

参照必须区分：

| 参照 | 内容与用途 |
|---|---|
| 原始 transcript | 判定是否有事实依据的主要来源 |
| transcripts.json 中的目标、actions 和 goalmodel | 访谈者整理的目标、动作与模型；属于人编参考，不能当作论文 LLM 输出 |
| extracted-goals / sampled-goals / summarized | 论文流水线不同阶段的生成目标；先核对生产脚本和实际字段再选定比较阶段 |
| models / graphs | 论文生成模型及图结构；辨明文档、运行次数和过滤规则 |
| comps_final 及配套文件 | 论文关系样本及双评审标签；保留分歧，核对评价脚本的裁决与方向处理 |
| 本项目三篇 development_reference | 开发诊断补充，不能作为独立测试 Gold |
| PPT 方法 | 目标模型完整性与分析能力的补充评价标准，不作为原始访谈事实 |

作者 README 明确区分访谈者模型与生成模型。本次读取 comps_final.csv 的字段为 G1、G2、rater1、rater2，确实存在评审分歧。另发现公开 RQ3 笔记本引用 comps.csv、graphs3.json，并保留与论文原报不同的历史结果；应核验最终文件和统计规则，不直接照抄缓存输出或猜测缺失文件替代关系。

## 二、Codex 执行流程

### 1. 建立输入清单和文档对应

按上游 ids、源文内容和哈希，将 DOCxxx 与论文各阶段数据对齐；数组下标不能直接当文档 ID。冻结输入清单、生成方信息、当前 skill 版本及评审规则。记录缺失的运行元数据。

同时核查论文正文所述轮次数与本地快照的差异；差异未解决时注明共同文档与共同文本范围，不宣称严格原实验复现。

### 2. 确定性核验

由 Codex 编写并运行本地工具，检查文件解析、引用、引文切片、重复项、版本、节点与边数量、连通情况和精化图无环。保留旧审计结果作为交叉核对，但统计以冻结的本次输入重算。

解析上游 Python 图代码时优先使用静态语法解析，仅支持确认过的构造，未知写法记为未解析；不直接执行仓库或输出中的任意代码。无法完整解析的图不静默丢弃，报告数量和影响。

### 3. 目标语义对应

以一篇访谈为一个处理单元。Codex 同时阅读源文和两方目标，为每项建立对应记录：

- 等价；一方更宽或更窄；部分重叠；一对多或多对一；单方新增；另一方缺失；无法确定。
- 记录双方原始 ID、原文目标、中文解释、对应证据、适用条件、判断依据及不确定点。
- 保留英文原始表述，不以中文翻译相同或向量相似度直接判定等价。
- 区分显式目标、合理推断的上层目标和无依据扩展；作者输出也可能有错误。

先固定目标对应规则，再进行关系比较。目标粒度不同不强行一一对应；不得为提高得分修改参照目标或本项目目标。

### 4. 关系和精化比较

分开完成三种任务：

1. 固定目标对上的关系判断：使用论文关系样本，隐藏 rater 标签后让 Codex 按既定口径判断，再揭示标签计算结果。这测量 Codex 的关系判断能力及评价器校准情况，不是现有 output 的建模成绩。
2. 已生成结果比较：在节点对齐后比较本地输出与论文图的方向性精化关系，分别统计直接边与传递闭包。输出未覆盖的目标和关系保留为未对齐，不统一当成无关系。
3. PPT/KAOS 模型质量评价：检查 Why/How 层次、AND 组、完整 OR 方案、贡献与冲突区分、场景条件、假设和未决问题。这是扩展评价，不能替代论文的二元精化指标。

KAOS 精化组不能无损降为普通二元边。为了与论文图对照而投影出的父子关系只能用于对应分析，原组语义必须保留并单独评分。

论文若同一访谈有多个生成运行，应按预先固定规则保留全部可比较运行并报告分布，或说明代表运行的选择依据，不能事后挑选最差或最好一次。

### 5. Codex 复核

评审先匿名显示 A/B，隐藏作者、agent 名称与已有评分；对争议、低置信度和代表性一致项交换呈现顺序复判。尽可能在不含首轮结论的新上下文中执行复核，并保存最终理由。

先用一部分已有标注样本校准评审规则，再冻结规则，在不同样本上检查表现，避免同一批样本既调规则又宣称独立测试。分别报告双评审一致样本、分歧样本和未判项。

Codex 判断统一标为“自动语义评审”，不冒充人工真值；多次调用不天然独立。用户只需按需要查看无法消解的争议与典型错误，完整人工重标不作为本轮启动前提。

## 三、结果指标与解释

| 维度 | 输出 | 解释边界 |
|---|---|---|
| 产物完整性 | 引文位置正确率、可解析比例、引用与版本检查 | 确定性事实，不等于语义正确 |
| 目标对应 | 等价/包含/部分重叠/拆合/新增/缺失/不确定计数，文档级覆盖 | 默认称参照对应率，不能直接称真实召回率 |
| 源文忠实性 | Codex 判断的完整支持、推断合理、条件遗漏、无依据扩展比例 | 写明自动评审口径与分母 |
| 关系样本 | 方向性 precision、recall、F1、混淆矩阵、拒判覆盖 | 在标签口径、样本范围及分歧处理已固定时计算 |
| 输出图关系 | 已对齐节点上的精化一致性、误连/漏连候选、直接边与闭包 | 同时报告对齐覆盖，不能只展示容易匹配的子集 |
| 模型能力 | 合理层次、精化组充分性、方案完整性、辅助关系与场景问题 | 按 rubric 给通过/部分/不足/不适用，并提供依据 |
| 使用成本 | 实测时间、调用、token、人工争议量 | 旧运行缺日志则记未知，不补估计数字 |

需要 precision/recall/F1 时先冻结可判定参考集和匹配规则，防止一个宽目标因匹配多个细目标重复计分。对 Codex 判断为有效的单方新增另报数量与依据，不把参照缺失自动解释为幻觉。

以文档为聚合和重采样单位，同时报告总体计数与文档间分布；小样本显示原始分母。层数、边数、连通率仅描述结构，不作为正确性分数。初期不设任意加权总分。

## 四、执行批次与交付

先用 DOC010、DOC023、DOC031 三篇完成格式、对齐和评审规则试运行；它们属于开发案例。规则冻结后处理其余 31 篇，分批保存结果与中断位置，最后合并汇总。整批仍属于已接触数据上的回顾性比较，不宣称未见泛化实验。

建议独立目录 runs/codex-comparison-YYYY-MM-DD/：

- input-manifest.json：来源、哈希、文档映射和运行元数据。
- protocol.md：冻结的比较规则、方向约定、分母和不确定项处理。
- per-document/DOCxxx.json 与 .md：逐目标对应、关系差异、证据和结论。
- goal-alignment.jsonl、relation-comparison.jsonl：可汇总机器记录。
- review-disagreements.jsonl：评审分歧、复判与待确认项。
- metrics.json 与 summary.md：分维度统计、优劣案例、覆盖范围和限制。
- 必要核验脚本与运行日志：支持复算，不依赖聊天记忆。

第一轮比较产出的问题用于修订 skill；新版冻结后在相同数据和相同评审规则下再次比较。直接结果比较可以立即开展；要进一步将变化归因于 skill，再补同模型、同输入、可比预算的受控重跑。
