# Skills 精简与最终模型输出方案

日期：2026-10-15；输出修订：2026-10-16。状态：用户认可四 Skill 精简方向与四种最终输出，继续实施和分项测试。

本文件更新此前六 Skill 的拆分方式；研究目标、证据标准和 S1/S2 边界保持有效。能力数量不等于 Skill 数量，也不等于模型调用次数。原方案作为设计历史保留，后续建设以本次方案经人工反馈后的版本为准。

## 1. 判断结论

六类能力均有用途，但当前按六个顶层 Skill 串行执行容易形成重复的输入组装、全文读取、语义判断与中间文档生成。特别是规范化与关系构建共享目标语义，验证与修复共享同一问题上下文，适合组织为同一 Skill 的不同模式。

提取时保留候选证据，与追溯时核对精确位置和完整语义支持，存在交叉但不宜完全合并。追溯需要处理他人提供或后续改写的目标，也承担独立检查职责。保留追溯入口有利于隔离“提出目标”与“验证依据”，但同一模型执行不等于独立审核。

原计划提到了目标图和机器数据，却没有指定谁负责统一组装目标节点、关系、证据、问题和版本，并输出一致的最终产物。新增目标模型构建 Skill，承接这项职责，同时容纳规范化和关系判断；不在六个串行环节后机械追加第七个。

## 2. 推荐结构：四个 Skill

| 顶层 Skill | 内部能力 | 主要输出 |
|---|---|---|
| goal-extraction | 资料接入、忠实转换、候选提取、初步分类 | 候选 JSON、默认候选审核 MD、源文附件 |
| goal-tracing | 引文定位、来源版本核对、语义支持 | 追溯 JSON、默认追溯审核 MD |
| goal-model-building（新增） | 目标规范化、关系判断、模型组装、最终交付 | 模型 JSON、默认模型说明 MD（含图）、必要附件 |
| model-review（待创建） | 确定性验证、语义疑点审查、局部修复提案与复检 | 问题报告、受限补丁、复检与版本记录 |

能力迁移：goal-normalization 和 goal-refinement 不再单建顶层目录，作为 goal-model-building 的可独立评测模式；model-validation 和 model-repair 不再单建顶层目录，合并到 model-review，但“发现问题”和“应用补丁”仍严格分开。

目前 extraction 与 tracing 已有文件；building 本轮仅创建初版供审核；review 尚未创建。不能把架构调整写成四个 Skill 已全部实现。

## 3. 两次使用构建 Skill，但不重复建模

```text
原始资料
  → goal-extraction：候选与源索引
  → goal-tracing：证据定位与支持
  → goal-model-building / assemble：规范化、关系判断、组装待检查模型
  → model-review：检查；必要时提局部补丁、应用副本、复检
  → goal-model-building / finalize：核对版本并导出最终产物
```

最后一次 finalize 只读取冻结模型及检查结果，用确定性工具核对和呈现，不重新提取、重判全部关系或补造目标；通常不需要额外模型调用。实质判断发生变化时必须回到相应构建模式并复检，不能一边导出一边悄悄修改语义。

规范化改变目标表述、来源集合或条件时，仅将受影响对象返回 tracing 重新核对，保留修订前后版本；不对未变对象重复完整追溯。关系端点需同时更新并检验，不能复用已过期的检查结论。

review 尚未实现时，可以输出明确标为“未检查”的模型草案，不得伪造已通过报告或正式发布模型。本轮新增 Skill 只定义流程，暂不声称已经存在编排和导出工具。

## 4. 处理成本来自哪里

| 成本来源 | 风险 | 控制方式 |
|---|---|---|
| 全文多次进入模型 | 各阶段重复读长访谈、OCR稿和转写稿 | 源文只转换一次；优先传目标表、证据片段和位置，必要时按需扩展上下文 |
| 指令与历史累积 | 同一长会话中旧 Skill 和中间结果并不会自动消失 | Runner 后续采用阶段化上下文；每次只组装相关指令和输入，不把整个对话发送给下一阶段 |
| 每步重生成整份模型 | 输出大量重复 JSON、引文与文档 | 中间结果存文件，局部改动传引用与补丁；最终产物统一组装 |
| 成对关系判断 | n 个目标有 n(n−1)/2 个无序对 | 首版小文档保留全对评估；规模扩大另评筛选策略和遗漏，未评估不得写成无关系 |
| 全模型反复修复 | 同一错误重复调用、改坏已正确部分 | 只处理问题关联子图，限制重试并检测无改善和重复哈希 |
| 中间人工文档重写 | 每阶段让模型改写同样的文字 | 从结构化结果渲染；独立调用各 Skill 仍交付约定的双输出，固定流水线可按用户需要集中呈现 |

“四个 Skill”不意味着输入 token 自动减少三分之一，也不保证调用次数下降。若把原来全部内容塞入一个更长提示而每次完整加载，可能更贵或更难发现错误。合并的收益来自共享有效上下文、按需读参考、局部重算和确定性工具，不来自目录计数。

源资料和证据全文可在最终可审计 JSON 中保存或通过可打包附件引用；大文件不必每次发送给模型。少传上下文不能以隐藏否定、主体或适用条件为代价。

## 5. 工具与模型的合理分工

- 确定性工具：文件哈希、字段投影、引文切片、ID/引用、边重复、自环/环、补丁前置条件、版本匹配、JSON/Markdown/图的渲染。
- 模型：目标分类、推断依据、语义归并、关系判断、语义疑点与修复建议。
- 人工：口径与初版审阅、歧义裁决、确认目标和关系、真实错误与修复有效性审核。

减少调用时仍保留关键检查。语义相似度或检查程序通过不能替代人工确认；相同模型拆成两次调用也不能冒称独立人审。

## 6. 最终模型交付要求

默认输出 goal-model.json、goal-model.md、离线交互 goal-model.html 与矢量 goal-model.svg。HTML 为用户主要查看入口，支持图浏览、筛选及点击证据；SVG 用于静态查看与论文汇报；Markdown 保留说明和审核记录。四者由同一权威 JSON 确定性生成，不重复调用模型生成语义内容。PNG/PDF 按需导出。

JSON 是模型权威数据，包含正式进入模型的目标、精化/相关等关系决策、证据引用、候选映射、排除记录、检查结果引用和历史版本。图只是有选择的视图，孤立目标、条件边、不确定项均不能被悄悄丢弃。

最终输出不要求树形、单根或全连通，也不凭空新增顶层目标。无源文支持的设计扩展须用户明确要求且单列；当前数据中的情境具体化不冒充严格 AND/OR 分解。

构建完成、结构检查通过、语义待审、人工采纳分别记录。存在阻断错误时仍可交付草案和问题说明，但不能标记为通过或正式发布。

## 7. 合并后仍能逐项评测

将规范化、关系判断、检查和修复保留为可显式选择的模式及独立中间产物，不再要求每个模式成为一个顶层 Skill。各模式的输入、输出、版本和实际使用参考均保存，继续支持单项测试与消融。

成本比较使用相同模型、文档、质量标准和预算上限，记录实际调用数、输入/输出 token、缓存使用（服务提供时）、耗时、重试与质量变化。若对比旧六阶段与新四 Skill 方案，须冻结两套实现；当前六阶段并未完整实现，无法直接给出节省比例。

## 8. 后续建设顺序

1. 人工审阅本方案与 goal-model-building 初版；未获得修改意见前不开展其行为测试。
2. 按已审核的 tracing 初版补齐可执行定位和双输出测试。
3. 修订并测试 building 的 normalize、relate、assemble 模式，先输出明确未检查的草案。
4. 创建 model-review 初版，人工建议后再修订测试。
5. 最后打通 review 后的 finalize，验证目标、证据、图和报告一致，再做固定流程成本与质量对照。

本次调整保留现有提取/追溯文件和测试记录，不重新执行已通过的提取测试，不删除开发数据，也不声称新增 Skill 已运行。
