# GoalForge 在 Codex、Claude Code、Gemini CLI 中的安装与使用指南

> 2026-10-18 更新：新版默认采用简明提取与 KAOS 层级模型，操作与输入输出见[新版审核说明](14-新版简明KAOS模型人工审核说明.md)。下文原分类、全对关系表、四输出和旧审核契约用于旧版；安装路径仍适用，安装时同步当前四项 Skill。

更新日期：2026-10-17。面向希望通过对话直接处理资料的使用者。

本文是操作指南，不代表已经执行安装。当前项目提供四项 Skill；统一入口 `goalforge` 尚未创建，不要调用它。已完成的工程测试与应用内真实运行验收是两件事：当前工程测试通过，三种应用的安装发现、模型执行和反馈修订仍需分别验收。

## 一、选择使用方式

建议先在 Codex 中使用项目级安装，让 Skill 只作用于当前项目。运行时由当前应用里的模型阅读资料、完成语义判断，由附带工具负责定位、核验、组装和导出；这种用法无需自行搭建额外的模型 API 服务。

| 方式 | 适合情况 | 操作 |
|---|---|---|
| 不安装，直接读取项目 | 先体验一次 | 在本项目对话中明确要求读取 `skills` 下四项 Skill |
| 项目级安装，推荐 | 持续在本项目处理资料 | 按下文复制四个目录到应用发现位置 |
| 用户级安装 | 希望所有项目可用 | 将完整四个目录安装到应用的个人技能位置；需检查同名冲突与访问权限 |

安装只让应用发现工作规范与资源，不会自动启动处理任务，也不保证语义判断正确。

## 二、安装前准备

1. 在应用中打开本项目：`D:\Desktop\summer_pro\GoalForge\GoalForge`。
2. 确认应用能读取你提供的资料，并能在项目内运行 Python、创建结果文件。Python 核心工具使用标准库；工程验证环境为 Python 3.9。Node.js 用于开发验证，不是普通用户生成模型的必需条件。
3. 第一次使用 MD 或 TXT 小样本，优先验证完整流程。Word、PPT、OCR 和录音的读取还依赖所在应用的工具，本项目尚未完成这些真实格式的端到端验收。
4. 若资料来自项目外，按应用提示提供访问权限，或把本次需要的资料副本放入项目，原件另行保留。

可以先向助手发送：

> 请检查本项目四项 GoalForge Skill 是否完整，确认当前能读取本次资料、运行 Python 并写出文件。只检查环境，暂不生成模型；说明无法处理的格式和缺少的工具。

## 三、安装四项 Skill

### 1. 复制什么

打开项目的 `skills` 文件夹，复制下面四个完整目录：

- `goal-extraction`
- `goal-tracing`
- `goal-model-building`
- `model-review`

每个目录下的 `SKILL.md`、`scripts`、`references`、`assets` 及其他实际存在的资源都要保留。不要只复制 `SKILL.md`，不要改目录名，也不要只安装其中一个：当前部分辅助工具会引用同级 Skill 的脚本。

### 2. 粘贴到哪里

以下均为“项目根目录下”的位置，文件资源管理器中没有时创建对应文件夹：

| 应用 | 推荐项目级位置 | 可选个人位置 |
|---|---|---|
| Codex | `.agents/skills/` | `~/.agents/skills/` |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Gemini CLI | `.agents/skills/`，也支持 `.gemini/skills/` | `~/.agents/skills/` 或 `~/.gemini/skills/` |

`~` 表示当前运行环境的用户主目录。本机原生 Windows 一般对应 `C:\Users\cjsmwy`；WSL、远程和云端环境的主目录不同，不会自动读取 Windows 的个人安装。

本机部分已装 Skill 位于 `.codex/skills`；此指南按当前官方文档使用 `.agents/skills`，不移动既有系统 Skill。若同时存在多个同名副本，先确认应用实际加载的路径，不重复安装。

例如 Codex 的最终结构为：

```text
GoalForge/
├─ skills/                         项目源文件，继续在这里维护
└─ .agents/
   └─ skills/
      ├─ goal-extraction/
      │  ├─ SKILL.md
      │  ├─ references/
      │  └─ scripts/
      ├─ goal-tracing/
      ├─ goal-model-building/
      └─ model-review/
```

不要多套一层 `GoalForge` 或 `skills`：应用应能在 `.agents/skills/goal-extraction/SKILL.md` 直接找到指令。

如果 Codex 和 Gemini CLI 使用同一个项目，可共用这里的 `.agents/skills`，无需重复复制到 `.gemini/skills`。Claude Code 使用自己的 `.claude/skills`。

### 3. 确认安装成功

安装后在同一项目新建一个对话，以便重新发现技能。检查应用的技能列表，或发送：

> 请确认能否发现 goal-extraction、goal-tracing、goal-model-building、model-review，并列出各项实际加载路径。请区分“应用已发现”与“你按路径临时读取”，暂不执行处理任务。

Codex CLI／IDE 可通过 `/skills` 或输入 `$` 选择 Skill；桌面端使用可用的技能选择器。Claude Code 可用 `/goal-extraction` 等命令；Gemini CLI 可通过 `/skills list` 检查，再在任务中点名所需 Skill。界面因应用版本可能不同。

能看到四项并能访问其附带资源后，再进入下一步。助手仅说“知道这些名称”不足以证明安装成功。

## 四、第一次生成目标模型

### 方式 A：分阶段，便于先核对候选

准备一份小型 MD/TXT 文件，附上文件或说明助手可访问的路径，发送：

> 请使用 goal-extraction 处理这份资料。本次只处理这个文件，不跨文件综合。先忠实读取并保留来源位置，再提取目标候选，同时输出 extraction.json 和 goal-candidates.md。保留分类理由、推断假设、识别疑点和不确定项；不要替我填写人工意见。完成候选后暂停，等我审核。

阅读候选文档，直接在对话中给出修改意见，例如：

> 第三项只是操作步骤，不是目标；第五项遗漏了“工作日”这一条件。请回查原文修订，保留旧版本。

候选适合继续处理后，发送：

> 请以当前候选版本继续，按 goal-tracing、goal-model-building、model-review 完成证据追溯、目标关系判断、模型组装和结构检查。由你依据原文编制当前版本的语义判断并维护中间文件，执行附带工具。最后交付可审核的 HTML、JSON、Markdown、SVG 和证据附件，记录限制，人工状态保持待审。

### 方式 B：一次完成初版

> 请按 goal-extraction → goal-tracing → goal-model-building → model-review 的流程处理这些资料。本次目标主体是……，范围是……。由你完成资料读取、目标提取、证据与关系判断、中间文件维护和工具执行，最终生成可人工审核的 HTML、JSON、Markdown、SVG 及附件。将结果另存到本次独立输出目录，保留原件。证据不足时标记不确定，不替我确认；生成初版后等待我的审核。

普通用户无需自己填写判断 JSON，也无需逐条运行工具。没有额外调用模型 API 时，判断由当前应用中的模型完成，仍应如实记录哪些检查实际运行过。

## 五、打开结果并审核

最终至少应收到以下四个文件及实际引用的附件、清单：

| 文件 | 你用它做什么 |
|---|---|
| `goal-model.html` | 查看目标图、目标与关系详情，填写审核意见 |
| `goal-model.md` | 阅读和分享文字说明 |
| `goal-model.json` | 供后续 Skill 和程序继续处理 |
| `goal-model.svg` | 查看或插入文档的静态目标图 |

请保留整个交付目录，尤其是 `attachments` 和清单文件，不要只留下 HTML。让助手提供可打开的入口；如果直接打开 HTML 不正常，可让助手在本机启动仅供本地访问的预览。当前已验证本地 HTTP 预览，直接 `file://` 打开尚未完成兼容性验收。

在 HTML 中：

1. 浏览目标图与目标卡片，核对主体、结果、条件和依据。
2. 对目标、关系或证据填写意见，并提交相应条目。
3. 查看未完成意见和整体审核状态；存在未解决争议时先保留待处理。
4. 使用页面的导出功能下载 `review-feedback.json`，文字版可一并保留。
5. 将导出的 JSON 交回对话，作为后续修改依据。

浏览器草稿只保存在当前浏览器环境；它不会自动写回模型，也不会自动发送给助手。更换浏览器、清除本地数据或换模型版本前先导出。整体认可必须由你实际作出，结构检查通过不能代替人工认可。

## 六、让助手应用审核意见

附上刚导出的反馈文件，然后发送：

> 请校验这份 review-feedback.json 对应的模型版本，并按我提交的意见修订副本。保留原模型和反馈记录；需要重新判断的目标和关系请依据当前原文重新处理，使用回填工具更新并复检。交付新版本四种输出、附件、修改说明和剩余问题。若反馈版本不匹配，请指出，不要强行套用；内容变化后的版本仍交我重新审核。

若只希望先看修改方案，改为：

> 先校验反馈并给出修改计划，暂不应用到模型。

修订后核对新版本的变化与剩余争议，再审核。可继续循环，直到你明确认可；未解决项应保留，不靠自动填写“已接受”结束流程。

## 七、更新和迁移

- **更新 Skill：**项目 `skills` 是维护源。修改源文件后，已复制的安装目录不会自动更新；保留旧版、同步完整四个目录，再在新对话确认加载路径。不要直接修改安装副本后忘记回同步。
- **换应用：**按新应用的发现路径安装同样四个目录，并重新检查 Python、资料读取、写入权限和预览能力。格式兼容不等于行为已验收。
- **换电脑：**同时迁移四个 Skill 和需要继续处理的完整模型包、原始资料及反馈。只有聊天记录或只有 HTML 不足以恢复证据核验。
- **云端使用：**本机安装和本机文件不会自动进入云端。需要把 Skill 与允许处理的资料提供到云端实际工作环境，并核对其执行工具；先用小样本验收。
- **停用：**移出或停用这四个安装目录，再开启新对话。不要删除项目维护源、原始资料和已产生的审核记录。

## 八、常见问题

| 现象 | 处理方式 |
|---|---|
| 找不到 Skill | 检查发现路径、目录层级和 `SKILL.md` 文件名，开启新对话，核对加载路径 |
| 提示缺少另一个脚本 | 检查四项是否完整、同级，目录名是否改变，是否漏复制资源 |
| 只能解释流程，没有输出文件 | 明确要求执行附带工具并提供实际文件；检查应用是否具备执行权限 |
| Word、PPT 或录音无法读取 | 让助手说明缺失工具；提供可靠导出稿或接入读取工具，保留原件与识别疑点 |
| 提示判断或检查报告过期 | 对当前输入重新生成判断并复检，不改哈希冒充新结果 |
| 已填意见的 MD 不允许覆盖 | 使用新的输出文件名，保留原审核文档 |
| HTML 意见没有进入对话 | 导出反馈 JSON 并附回对话；浏览器草稿不会自动同步 |
| 新版本仍显示待审 | 内容发生变化后需要重新审核，不继承旧版人工认可 |

## 九、首次验收清单

先用新建的小型资料完成以下步骤，再扩大材料规模：

- 应用确实发现四项 Skill，并能访问完整资源。
- 模型依据本次资料生成候选与新的判断，没有读取参考答案或复用旧结论。
- 实际产出四种最终视图，能打开 HTML，目标、证据和关系一致。
- 在 HTML 修改一项，导出反馈，交回助手并生成修订副本。
- 新版本完成复检，原件、旧模型和反馈保留，人工状态与真实决定一致。

当前工程验证为 71 项 Python 测试、7 项 JavaScript 测试通过，受控演练含 24 次工具调用、17 项流程检查；这些结果不代表三种应用均已实测，也不代表真实资料的语义准确率。详见[修复验证记录](09-审核问题修复方案与验证结果.md)。
