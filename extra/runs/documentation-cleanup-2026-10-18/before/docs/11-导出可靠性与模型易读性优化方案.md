## 二、优先修复导出：内容能取出，状态说清楚

### 1. 分清两类导出

| 用户需求 | 推荐主按钮 | 内容 |
|---|---|---|
| 把审核意见交回助手 | 导出审核意见 | 正式反馈 JSON；有未完成表单时指出具体位置，另允许保存草稿 |
| 临时保存进度 | 保存审核草稿 | 包含未完成表单的草稿 JSON |
| 阅读或分享意见 | 导出可读摘要 | Markdown，并标明草稿或正式状态 |
| 获取当前模型 | 导出模型文件 | 模型 JSON、说明 MD、SVG；与意见分开，说明这是当前快照 |

取消把“提交”与“已送达助手”混为一谈。正式导出仅代表生成意见包，需用户附回对话后才进入处理；不自动修改模型或替用户认可。

### 2. 一个导出面板，提供多条取出路径

点击后先展示将导出的文件名、格式、当前模型版本、意见数量和草稿状态，再提供：

1. **保存文件：**环境支持保存选择器时可使用它；否则使用浏览器下载。能力判断后降级，不要求用户修改安全设置。
2. **复制完整内容：**下载未发生或受限制时可直接复制 JSON 给助手；剪贴板不可用时展示可选择的完整文本并提供手动复制说明。
3. **查看导出内容：**只读预览同一份真实内容，明确编码和建议文件名，不截断复制数据。

三条路径消费同一份经校验的数据快照。保留版本绑定，不为兼容性绕过反馈校验。文件名包含模型标识、版本和时间，减少重复下载后的混淆。

### 3. 区分导出状态

- 校验不通过：显示问题和“前往该项”，保留用户输入；同时允许保存合规草稿。
- 正在生成：避免重复触发，失败后恢复操作。
- 保存选择器写入完成：有实际完成信号时才能提示已保存。
- 浏览器下载请求已发出：提示检查下载列表；不声称文件已落盘。
- 保存取消或异常：明确说明，保留内容，提供复制与预览。

只有获得实际成功信号或用户明确确认后才记录相应保存状态；不能仅凭触发链接更新“已备份”的标记。下载失败不得清空草稿或将其转为人工接受。

### 4. 避免模型附件链接断裂

优先让交付 HTML 内置模型 JSON，并在生成时内置同版本可读文本与 SVG 的导出载荷，由页面直接生成下载内容；避免按钮只能依赖旁边的文件。仍保留完整交付包及附件，说明内置的模型视图不是原始资料备份。

明确区分“模型四视图”与“完整证据交付包”。若支持整包下载，必须实际包含声明的附件并核验清单，不能只把 HTML 压缩后叫完整包。大文件或受限环境下继续由助手交付已有完整目录。

## 三、降低理解成本：目标优先、疑点优先、详情按需

### 1. 默认进入简明阅读页

首屏只回答三个问题：资料涉及什么、有哪些目标、哪些地方需要我确认。

- 一段有依据的概览，说明处理范围、目标主体、目标数量和关键限制，不新增原文未支持的总目标。
- 默认显示目标卡片；每张卡片先显示一句完整目标、直述或推断标识、审核状态和“查看依据”。
- 目标过多时可按来源或已有可靠分类分组。新主题分组只作为展示导航，明确不是模型上下级关系。
- 隐藏关系图工具、技术编号、哈希和完整检查状态，提供“模型详情”入口。
- 默认摘要不能删掉否定、条件、数字或主体；标题缩短时完整目标可直接展开。

### 2. 保留关系图，变成第二层探索

图在用户点击“查看目标联系”后打开。先展示所选目标及其一跳联系，全景图作为可选高级视图。

- 默认只绘制已建立的关系，不画没有关系的目标对，不把不确定关系画成成立的边。
- 用自然语言解释，例如“两个目标存在联系”“这是同一目标在更具体情境下的表达”，专业名称放在帮助中。
- 不把“相关”改画为因果、先后或上下级；没有精化层级时继续显示独立目标，不为好看造树。
- 点击连线后再展示关系理由、条件、证据和审核入口。
- 清单模式不展示缩放、关系范围和图例；图模式才显示相应操作。

### 3. 审核从逐项目标开始

常规用户默认看到“目标已审 X/Y、待确认 Z”，而非将所有两两组合平铺为 56 项任务。

采用“目标内容 → 关键疑点 → 意见汇总”的引导流程，每屏保留一个主要动作：

1. 逐项目标：目标、原文、必要上下文和“认可／需修改／暂不确定”。合并、拆分、排除放入更多操作。
2. 关键疑点：优先检查推断、证据不足、冲突和不确定关系；按对象归并展示，但保留每条原始问题及跳转。
3. 汇总：展示实际意见、未处理事项和导出入口。

专家模式仍提供全部关系判断、证据、检查信息和完整进度。简化默认展示不会删除记录，也不等于免除审阅：目标看完不能自动认可全部关系、证据或完整模型。完整认可仍需明确范围与限制确认。

### 4. 减少术语与移动端负担

“显式目标”显示为“原文直接表达”，“推断目标”显示为“根据原文推断”；专业术语在帮助或高级模式保留。版本信息可查看，哈希等内部信息折叠。

移动端使用单列，目标详情与审核按页面或清晰步骤切换，避免在弹窗里同时横向滚动任务列表与纵向滚动编辑区。保存与返回可见，键盘焦点、错误定位和屏幕阅读提示随状态更新；不只靠颜色传达类别和结果。

| goal-model-building | 默认简明视图、按需关系图、同版本内置导出载荷、失败替代路径及实际导出验收 |

## 五、实施顺序与验收

1. **导出修复：**分别复现正式意见、草稿、摘要、模型 JSON/MD/SVG，记录打开环境与失败类型；实现导出面板、状态反馈、复制及文本兜底。
2. **简明阅读与审核：**默认目标卡片、疑点引导和局部关系图，高级视图保留完整数据。
3. **同步规则与交付：**更新 Skill、说明和真实示例，保留旧交付与用户草稿，生成新版本，不覆盖旧意见。

验收至少包括：

- 每类下载得到真实文件并核对 JSON 可解析、中文正确、版本一致；导出的反馈可回读、校验、导入并进入后续修订。
- 验证取消保存、校验失败、剪贴板不可用、重复点击、下载无可观察完成信号，以及只带 HTML 时的模型视图导出。
- 分别核查 Codex 内嵌预览、普通浏览器本地 HTTP 和直接文件打开；不能运行的环境明确标为未验证。
- 使用新小样本完成“浏览目标→对照原文→提出一项修改→导出→交回→生成新版本”，不靠预置空草稿证明完整成功。
- 9 个目标、无层级、无目标、目标较多、长文字、小屏和键盘操作均可用；不确定关系和展示分组不改变真实模型含义。
- 邀请实际使用者完成首次审核，观察能否找到依据、解释目标联系并带走意见；工程测试不能替代理解程度验证。

优先级：先保证意见能够可靠取出且不丢失，再调整默认阅读和审核方式，最后完善高级图形展示。所有体验简化都保留证据、版本与人工决定边界。
