# 四项 Skill 的输入、输出与衔接

> 2026-10-18 更新：新版默认采用简明提取与 KAOS 层级模型，操作与输入输出见[新版审核说明](14-新版简明KAOS模型人工审核说明.md)。下文原分类、全对关系表、四输出和旧审核契约用于旧版；安装路径仍适用，安装时同步当前四项 Skill。

更新：2026-10-16。使用者可以提供普通材料和自然语言说明，文件读取、内部编号及结构化整理由助手完成，不要求用户手工填写 JSON。

使用步骤见[完整操作手册](07-完整流程操作手册.md)。[流程审核](08-全流程审核报告.md)发现的问题已按[修复方案](09-审核问题修复方案与验证结果.md)处理，当前支持版本绑定判断和自动回填；新的语义判断仍由助手编制，不是无人值守推理管线。

## 1. goal-extraction：从原始资料得到目标候选

**用户输入**：粘贴文字、MD/TXT、Word、PPT、PDF、图片/扫描件、录音或既有访谈，及允许处理的范围。可说明希望使用的人工审核文档格式。

**内部处理**：清点材料，保留原件，忠实转为可处理文本并保存页码、段落、幻灯片或时间段映射；再区分目标、动作、障碍、偏好与不确定项，保留原句、分类理由和推断假设。

**主要输出**：

| 文件 | 内容与用途 |
|---|---|
| extraction.json | 权威候选数据，含资料/转换信息、来源片段、覆盖范围、候选ID、类别、目标表述、原句、推断及待审问题；供后续Skill/Agent复用 |
| goal-candidates.md | 默认中文人工审核文档，逐项展示相同候选及依据，保留人工意见空栏；可按用户要求改用其他文档格式 |
| 转换稿及来源附件 | 当前原生文本工具使用source.txt和source-input.json；其他格式保存实际转换结果和原件定位，文件名随工具而定 |

**下一步**：将 extraction.json、标准全文和来源附件交给 goal-tracing。动作、障碍等仍保留用于解释，不自动成为目标节点。

**已验证范围**：原生文本/项目访谈读取、候选审核文档与关键校验。Word/PPT/OCR/录音是接入设计范围，需调用实际可用读取/转写工具；尚未完成这些格式的真实端到端验收，不能声称已全部处理成功。

## 2. goal-tracing：核对每个目标的证据

**用户输入**：已有目标/候选及其原始资料，通常直接使用上一步文件；也可提供改写后的目标与对应原件。

**机器输入**：当前脚本接收extraction.json、标准全文以及版本绑定的语义判断包。先生成空白模板，再由助手依据本次材料填写；输入哈希或目标表述不匹配、旧平铺格式均被拒绝。缺少判断时明确记录semantic_not_run，不自动调用模型。

**主要输出**：

| 文件 | 内容与用途 |
|---|---|
| tracing.json | 沿用目标ID和版本，保存提交/新增引文、来源、Unicode位置、匹配状态、语义支持程度、推断步骤、假设及问题 |
| goal-tracing-review.md | 中文人工核对文档，展示目标、原句、位置、支持判断与风险，保留人工意见栏 |

位置状态区分精确命中、歧义、未命中和来源不可用；语义支持区分直接支持、推断支持、证据不足和相反证据。位置命中不自动等于语义支持。此阶段不改目标、不判断目标间关系。

**下一步**：将候选、tracing.json及证据附件交给 goal-model-building。语义变更后的目标需重新追溯；目前脚本主要处理提取候选格式，审核反馈处理已能生成retrace-input.json，保留goal_id与新模型版本绑定；助手需提供新的语义判断，不能直接沿用旧支持。

## 3. goal-model-building：构建模型并交付可视化

**用户输入**：已有候选与证据、目标清单、已有目标模型，以及允许的归并/改写/关系建议。只有原件时先完成候选提取。

**机器输入按阶段提供**：

| 模式 | 输入 | 阶段输出 |
|---|---|---|
| assemble | extraction.json、tracing.json、冻结节点全部目标对的关系判断、标准全文；可选规范化节点JSON | model-input.json及attachments/输入副本：供model-review检查的模型草案 |
| finalize | 被检查的模型JSON、对应review-report.json、实际证据附件 | 下列四份最终视图及交付清单；不重新做语义判断 |
| reconcile | 修订模型、匹配版本的重追溯输入/结果/判断及关系重评文件 | reconciled-model.json、复检报告、回填记录与实际附件，再交finalize |

规范化和关系判断由助手完成并留成独立决策输入；脚本负责组装与一致性，不从目标文字自动推断关系。关系包括精化、相关、等价建议、无关系和不确定；图中只画精化/相关，其他判断完整保留在数据与清单中。

**主要交付**：

| 文件 | 内容与用途 |
|---|---|
| goal-model.json | 权威目标模型：节点、关系决策、图边、证据索引、来源映射、问题、检查和版本；供系统复用 |
| goal-model.md | 中文模型说明，包含目标图、节点、关系、证据、限制和人工意见栏 |
| goal-model.html | 模型查看与人工审核入口，提供图/清单、原文、逐项意见、草稿恢复、反馈导入/导出及整体决定；不直接覆盖模型 |
| goal-model.svg | 静态矢量总览图，用于放大查看、汇报或文档引用 |
| delivery-manifest.json、attachments/ | 文件完整性清单、源文与阶段输入、匹配版本的检查JSON和中文报告 |

四份视图来自同一模型，不分别生成不同内容。HTML资源内嵌、不需要在线服务；本环境只完成HTTP本地预览和无外部依赖验证，直接打开本地文件仍待用户浏览器验收。

**下一步**：assemble草案交model-review；检查或修复后回到本Skill的finalize，再交用户在HTML填写审核。导出的review-feedback.json交回model-review处理，形成新版本并复检。草案也可导出四视图，但状态是unchecked/blocked，不冒充已验收。

## 4. model-review：检查、提出局部修复并复检

**用户输入**：已有目标模型、来源/追溯附件，及“仅检查 / 提建议 / 修复”的要求。用户不必自己写补丁。

**机器输入**：model-input.json或其他符合契约的模型JSON；其input_artifacts声明的附件；repair模式另需明确的patches.json。人工反馈处理另接收HTML导出的review-feedback.json。

**主要输出**：

| 模式 | 输出 |
|---|---|
| inspect | review-report.json：版本绑定检查、问题和未执行项；model-review.md：同一内容的中文人工审核文档 |
| propose | 上述报告，加patches.json：问题ID、基准版本/哈希、修改前后值及理由；目前自动建议仅覆盖唯一可确定的关系计数纠正 |
| repair | 上述报告与实际尝试记录、补丁副本；仅成功保留的事务生成repaired-model.json及证据附件。失败整体回滚，不生成伪成功模型 |

当前检查工具核对结构/引用/精化环/关系覆盖、目标来源映射、文档范围、附件哈希、原句偏移和实际人工反馈记录。局部补丁脚本只允许白名单字段替换；人工反馈处理可委托构建模块执行明确的目标增删/合并/拆分。涉及含义的变化使相关证据支持失效，必须重新追溯。

**人工反馈额外输出**：feedback-processing.json/.md保存逐项去向；--apply后输出feedback-model.json、实际反馈附件与复检报告，review-tasks.json列出需重判断项，来源完整时另有retrace-input.json。默认处理计划不改模型。

**下一步**：将未变更模型、repaired-model.json或feedback-model.json及其当前review-report.json交goal-model-building.finalize。新增/删除/归并节点返回构建阶段；证据语义失效返回追溯阶段，再复检。

## 整体流转与当前状态

```text
用户原始资料
  → goal-extraction：候选JSON + 人工候选文档 + 转换附件
  → goal-tracing：追溯JSON + 人工追溯文档
  → goal-model-building.assemble：模型草案 + 输入附件
  → model-review：检查报告 → 必要的局部补丁 → 复检
  → goal-model-building.finalize：JSON + MD + HTML + SVG + 清单/附件
  → 用户在HTML逐项审核 → 导出review-feedback.json
  → model-review校验/处理意见 → 必要的新版本与复检 → 再次交付
```

| 状态 | 当前含义 |
|---|---|
| 结构passed | 本版本实际执行的机械检查通过，不证明语义正确 |
| 语义not_run | 未执行独立语义审查模型；保留上游助手判断和待审疑点 |
| 人工pending/partial/accepted | 未确认／已有部分意见／用户明确认可完整版本；内容变化后认可失效 |
| 交付reviewable | 检查结果匹配且无阻断项，可供人工审阅，仍可能有不确定关系 |

四项Skill已形成项目内文件、辅助工具及开发运行记录，当前71项Python和7项JavaScript测试通过。DOC023既有结果仍为9目标、36项关系、6项关系待审；本次修复未重新判断它的内容。独立模型API/Agent调度、真实多格式验收、独立语义质量与成本评测仍未完成；四项Skill尚未安装为Codex自动发现能力。

输入和输出中的技术JSON由助手/工具维护，普通使用者可直接在最终HTML中填写意见，导出审核文件交回本对话；技术JSON由工具维护，无需手工编辑。详细操作见[审核界面使用说明](06-人工审核界面与反馈处理说明.md)。
