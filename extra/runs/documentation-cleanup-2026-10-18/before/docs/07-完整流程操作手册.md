# GoalForge 完整流程操作手册

> 2026-10-18 更新：新版默认采用简明提取与 KAOS 层级模型，操作与输入输出见[新版审核说明](14-新版简明KAOS模型人工审核说明.md)。下文原分类、全对关系表、四输出和旧审核契约用于旧版；安装路径仍适用，安装时同步当前四项 Skill。

适用版本：2026-10-16 的四项项目内 Skill。面向普通使用者；技术协作者可阅读文末附录。

若要在 Codex、Claude Code 或 Gemini CLI 中安装并直接调用，请先阅读[主流 Harness 安装与使用指南](10-主流Harness安装与使用指南.md)。本手册中的“尚未安装”描述项目当前交付状态；安装后的调用以新指南为准。

本流程由使用者、当前对话中的助手和本地辅助工具共同完成。助手负责读资料、整理判断、运行工具和维护文件；你负责提供资料、核对原文、填写审核意见和决定是否采纳。当前没有自动模型API或无人值守Agent，四项Skill也尚未安装为Codex自动发现能力。

修复前审核记录见[全流程审核报告](08-全流程审核报告.md)，当前修复和验证见[修复方案与结果](09-审核问题修复方案与验证结果.md)。三处缺陷与回填工具缺口均已修复，工具回填闭环已验证；新的语义判断仍由助手或可用模型依据当前资料编制，不是无人值守语义推理系统。

## 一、先看整体过程

```text
提供资料及范围
  → 忠实转换资料
  → 提取目标候选
  → 核对原文证据
  → 整理目标并判断关系
  → 结构检查、必要修复和复检
  → 生成可审核HTML及JSON/MD/SVG
  → 用户填写并导出审核意见
  → 助手校验意见，按要求形成计划或应用到副本
  → 重新追溯、评估受影响关系并复检
  → 新版本再次交付，用户确认后归档
```

| 阶段 | 你需要做什么 | 助手负责什么 | 主要可读结果 |
|---|---|---|---|
| 资料接入 | 提供原件、范围、不可处理内容的说明 | 清点材料、保留原件、转换并标记缺失和识别疑点 | 转换说明与来源位置 |
| 目标提取 | 可提出遗漏、误解或分类意见 | 区分目标、动作、障碍、偏好与不确定项 | goal-candidates.md |
| 证据追溯 | 核对目标是否忠实表达你的资料 | 检查引文位置，判断直接支持、推断、证据不足或相反证据 | goal-tracing-review.md |
| 模型构建 | 补充允许的目标/关系建议 | 整理表达、保留来源，判断关系、记录不确定项 | 模型草案 |
| 检查交付 | 查看问题与限制 | 检查结构、引用、版本与附件，生成统一视图 | goal-model.html及说明文档 |
| 人工审核 | 在HTML填写意见，导出审核文件 | 保持原模型快照，收集反馈 | review-feedback.json和.md |
| 意见处理 | 说明只看建议还是应用意见 | 校验版本/冲突，在副本处理并记录去向 | feedback-processing.md与新版本 |
| 最终确认 | 对新版本明确决定 | 核对真实认可记录，打包模型和依据 | 有版本、状态与附件的最终交付包 |

## 二、准备资料与发起任务

### 1. 提供什么材料

可以提供粘贴文字、MD/TXT、访谈、Word、PPT、PDF、图片或扫描件、录音。实际读取取决于当前可用工具：原生文本与项目访谈已验证，Word/PPT/OCR/录音尚未完成真实端到端验收。遇到不可读内容，助手应标明处理范围，提供可靠部分和缺失说明。

建议同时说明：

- 本次研究什么问题，以及目标属于谁。
- 允许处理哪些材料、页码或时间段；是否允许跨文件综合。
- 哪些内容是原始陈述，哪些是你后补的解释或建议。
- 是否有必须保留的主体、条件、数字、时间和否定表达。

用户不必准备内部编号或JSON。原件保留，转换稿另存；关键识别错误先核对，不能把不确定转写当成已确认原话。

### 2. 可以直接这样发起

> 请按照当前项目 skills 目录中的四项 Skill 处理我提供的资料。本次范围是……，主要关心……。先忠实转换资料，保留原件位置，再提取目标、追溯证据、构建并检查模型，最后交付可直接填写审核意见的HTML及JSON、MD、SVG。请记录实际处理范围、无法处理部分和需要人工判断的事项。

因为Skill尚未安装，明确引用“当前项目skills目录”即可由助手读取执行，不必使用尚未注册的快捷调用名称。

## 三、首次模型生成时看什么

### 1. 先核对转换稿

检查说话者、顺序、否定、条件、数量、页码或时间段，重点查看识别疑点。转换稿是忠实读取结果，不应只剩摘要。资料有缺失时，先判断缺失是否影响本次目标。

### 2. 查看候选文档

打开goal-candidates.md，检查目标是否表达期望结果；动作、障碍和偏好是否被误当成目标；推断是否说明理由和假设。可以直接在对话中说明“候选X遗漏了条件”“这项只是操作步骤”等意见。

填写过人工意见的Markdown应另存保留。候选文档生成器默认拒绝覆盖已有文件，重新生成时使用新路径，保留历史版本和已有手写意见。

### 3. 查看证据追溯

逐项目标核对原句是否属于正确主体、条件和时间。这里有三个不同的判断：

| 信息 | 表示什么 | 不能据此认定什么 |
|---|---|---|
| 引文位置精确命中 | 工具找到了相同原文及位置 | 目标含义一定被完整支持 |
| 直接/推断支持 | 助手根据当前资料形成的支持判断 | 已经独立复核或获用户认可 |
| 独立语义审查not_run | 尚未执行另一次独立语义质量检查 | 全流程从未做过任何语义判断 |

目标改写后，要重新判断新增含义。当前工具强制核对语义判断的输入哈希和完整目标表述；旧判断即使编号相同也会被拒绝。助手先生成本版本空白模板，再读取原文填写新判断，不自动给旧结论补新哈希。

### 4. 查看模型关系

精化是有依据的范围或情境具体化，父目标指向子目标；相关表示存在联系；等价是待处理的归并建议。没有精化关系、存在多个根或孤立目标，都可以是合理结果。

“未建立关系”仅限当前资料，“不确定”表示已判断但无法确定；修改后尚未重新判断的关系应另标未评估，不能用“无关系”填充。

## 四、在HTML中完成人工审核

### 1. 打开入口

当前示例是[DOC023可审核模型](../runs/skill-tests/human-review-v1/delivery-v4/goal-model.html)。本会话的[本地预览地址](http://127.0.0.1:8768/delivery-v4/goal-model.html)在预览服务运行期间可用。

如果文件或地址打不开，在对话中说“请为最新模型启动本地预览”。当前环境验证了本地HTTP预览；直接双击本地HTML的兼容性尚未完成单独验收。

### 2. 点击“开始审核”

默认优先显示推断目标和疑点；你也可以切换“全部目标”“全部关系判断”“全部证据”“整体与遗漏建议”。图中没画出的无关系和不确定判断也应能审核。

“未填写”是尚未记录意见，“已记录意见”包括认可、修改建议和暂不确定，不代表已认可。

### 3. 对照原文填写

| 对象 | 可选意见 | 填写要求 |
|---|---|---|
| 目标 | 认可、修改、排除、合并、拆分、暂不确定 | 修改填写建议表述；合并选择目标；拆分每行一项；修改和待定说明理由 |
| 关系 | 认可、修改、暂不确定 | 修改类型、精化方向或条件，并说明原文依据 |
| 证据 | 支持充分、部分支持、证据不足、引用或位置错误 | 对部分支持、不足和错误说明具体问题 |
| 整体 | 总体意见、建议补充目标 | 新目标选择已有原文依据；新增资料通过对话补交 |

填写后点击“记录此项意见”。未完成的表单可以暂存，提交前需记录或放弃。可以撤回已经记录的意见；这些操作不会直接覆盖模型。

合并/排除某目标，同时又单独认可或修改该目标，可能形成冲突。关系意见若引用将被排除的目标，也需要先协调。助手应列出冲突，不自行猜测优先级。

### 4. 查看汇总并作整体决定

点击“汇总与导出”，可填写审核人名称和整体意见。名称是自填信息，不是身份认证。

- 仅填写部分项目：保存为部分意见，其他内容仍未审核。
- 有修改、争议或待定：选择需要修改/继续核对。
- 认可完整当前版本：明确确认已审阅完整范围及检查限制，且没有未完成表单或未解决意见。

认可保留“不确定”这一判断，不等于断言那条关系已经成立。结构检查、独立语义审查和人工决定始终分别显示。

## 五、保存、导出与继续审核

| 文件/方式 | 用途 | 可否交给助手应用 |
|---|---|---|
| 浏览器暂存 | 编辑时的便利备份 | 需要先导出文件 |
| review-feedback-draft.json | 未完成审核，可导入继续，含未完成表单 | 不作为已提交意见直接应用 |
| review-feedback.json | 点击“提交审核并导出”后下载的完整反馈 | 可以，助手先校验版本与内容 |
| review-feedback.md | 可读的意见摘要 | 可用于阅读沟通；结构化交接优先用JSON |

点击下载后确认文件已保存。浏览器地址、浏览器或缓存变化时，暂存可能无法恢复；导出的JSON是可靠的交接材料。

下次点击“导入审核文件”，选择JSON，查看版本检查结果，再明确点击替换。导入不一致的旧版本文件会被拒绝，当前草稿应保留。首版不自动合并多人意见，先将不同人的反馈分别交给助手协调。

## 六、把审核意见交回助手

### 仅查看处理建议

上传review-feedback.json并说明：

> 请校验这份反馈对应的模型版本，列出意见冲突、预计修改和需要补充的资料，先给出处理计划。

### 应用明确意见

上传review-feedback.json并说明：

> 请核对反馈版本和冲突，按这份已提交意见在副本上修改，保留原模型与来源映射。对受影响目标重新判断证据支持，重新评估相关关系，复检后交付新版本。未解决项请继续保留，不自动继承旧版本认可。

同一项目对话中，助手通常能取得原模型和附件；换电脑或新环境时，应同时提供匹配版本的完整模型目录。只有反馈文件不足以核验全部原文。

助手应交付feedback-processing.md，逐项说明已应用、待重新追溯、待关系重评、存在冲突或仍需人工决定。证据争议会同时检查目标和关系的直接引用；即使没有受影响目标，也会列出受影响关系，失效后由构建阶段重新判断。

## 七、新版本如何重新检查与确认

1. 目标或证据变化后，助手读取review-tasks.json及可用的retrace-input.json，重新编制语义判断，检查原文位置和新增含义。
2. 对相关目标对重新判断关系，保留无关系、不确定与未评估的区别。
3. 助手使用reconcile_model.py接收实际追溯输入、追溯结果、绑定判断和关系重评包。工具核对版本并重新执行定位，自动回填副本，处理新旧证据编号冲突，保留候选映射、变化记录和父版本。仅生成tracing.json仍不表示模型已更新，需要实际执行回填。
4. 对实际更新后的模型重新inspect，再使用匹配版本报告finalize；旧检查报告不继续作为通过依据。
5. 查看新版本HTML及意见处理说明，确认建议是否正确应用。内容变化后，旧人工认可不适用于新版本。

如果复检仍有阻断项，继续交付带说明的草案；如果只有原文无法裁决的疑点，可以明确保留不确定性，由你决定是否采纳该表达。整体认可后，应保留实际反馈文件及对应内容标识。

## 八、读懂状态与归档文件

| 状态 | 实际含义 | 下一步 |
|---|---|---|
| unchecked | 没有匹配当前版本的有效检查 | 要求助手检查 |
| blocked | 存在阻断项，可能是待追溯、未评估关系或坏引用 | 查看问题清单并处理 |
| reviewable | 机械检查通过且无阻断，可供审核 | 用户核对内容 |
| pending | 没有整体人工认可，或新内容需重审 | 填写意见 |
| partial | 已记录部分人工意见 | 继续审核或明确整体决定 |
| accepted | 有绑定当前内容版本的明确人工认可 | 保留反馈与交付包；不视作语义正确性证明 |

归档时保留整个交付目录：

```text
goal-model.html          模型查看与审核入口
goal-model.json          权威模型
goal-model.md            可读说明
goal-model.svg           汇报或引用用矢量图
delivery-manifest.json   文件完整性清单
attachments/            原文、阶段输入、检查报告及实际人工反馈
```

不同版本分别存放。不要只转发截图后丢失JSON、源文及意见；截图不能恢复模型和审核过程。

## 九、常见问题

| 问题 | 处理方式 |
|---|---|
| 点击“提交”后模型没变 | 提交准备并下载意见文件；把JSON交回助手后才进行模型处理 |
| 只有草稿文件 | 导入继续填写，再通过提交按钮生成submitted反馈 |
| 整体认可不能选择 | 检查范围/限制确认、未完成表单、修改/争议/待定项及模型阻断状态 |
| 反馈提示版本不一致 | 提供对应旧模型或在新版本重新审核；由助手列出差异后协调 |
| 图中没连线 | 查看全部关系判断；可能没有精化、存在孤立目标或关系尚未评估 |
| 重追溯仍是支持不足 | 检查是否尚未提供新的语义判断；位置命中不会自动恢复direct |
| 只有部分重判断已完成 | 先回填已完成部分，未评估关系继续阻断；补齐当前版本的其余判断后再回填、复检 |
| Word/PPT或录音不能读取 | 让助手说明可用读取工具和失败范围，必要时提供可靠导出稿并保留原件映射 |
| 生成文档提示文件已存在 | 原文件被保留；请助手使用新的输出路径生成修订版 |

## 附录：技术协作者执行入口

普通使用者无需执行以下命令。路径相对于项目根目录；尖括号内容是需替换的占位符，每次使用新的阶段目录。

```text
python skills/goal-extraction/scripts/prepare_source.py <原生MD/TXT或源文JSON> <资料目录>
```

准备工具不会提取语义候选。助手根据标准全文形成extraction.json后，再生成审核文档；候选和语义/关系判断文件都应留档。

```text
python skills/goal-extraction/scripts/render_review.py <extraction.json> <新的goal-candidates.md路径>
python skills/goal-tracing/scripts/trace_candidates.py <extraction.json> --judgment-template <新语义模板.json>
```

助手依据当前目标和原文填写模板的label、理由及支持/不支持部分，另存判断文件，再运行：

```text
python skills/goal-tracing/scripts/trace_candidates.py <extraction.json> <追溯目录> --source <source.txt> --judgments <本版本绑定语义判断.json>
python skills/goal-model-building/scripts/assemble_model.py <extraction.json> <tracing.json> <relation-decisions.json> <组装目录> --source <source.txt>
python skills/model-review/scripts/review_model.py <model-input.json> <检查目录>
python skills/goal-model-building/scripts/finalize_model.py <被检查模型JSON> <review-report.json> <交付目录>
```

反馈接收分为计划与应用：

```text
python skills/model-review/scripts/process_feedback.py <goal-model.json> <review-feedback.json> <计划目录>
python skills/model-review/scripts/process_feedback.py <goal-model.json> <review-feedback.json> <修订目录> --apply
python skills/goal-tracing/scripts/trace_candidates.py <修订目录/retrace-input.json> --judgment-template <新目标判断模板.json>
python skills/goal-model-building/scripts/reconcile_model.py <修订目录/feedback-model.json> --relation-template <新关系模板.json>
```

助手填写本版本的新判断文件后，执行：

```text
python skills/goal-tracing/scripts/trace_candidates.py <修订目录/retrace-input.json> <新追溯目录> --source <修订目录/attachments/source.txt> --judgments <新目标判断.json>
python skills/goal-model-building/scripts/reconcile_model.py <修订目录/feedback-model.json> <回填目录> --retrace-input <修订目录/retrace-input.json> --tracing <新追溯目录/tracing.json> --judgments <新目标判断.json> --relations <新关系判断.json>
python skills/goal-model-building/scripts/finalize_model.py <回填目录/reconciled-model.json> <回填目录/review-report.json> <新交付目录>
```

回填工具已实际复检，不必重复同一检查；finalize仍会核对版本和附件。只有关系需要重评时，reconcile只传--relations即可。只先提交追溯也可以，未完成的关系继续阻断。新关系引用本次追溯证据时使用trace:E0001等明确名称，由工具映射到不覆盖旧索引的新编号。详细契约见[回填说明](../skills/goal-model-building/references/reassessment.md)。
