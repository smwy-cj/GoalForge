# 建模判断与分模式执行

> 旧版二元关系模型规则；新任务按 [KAOS 简明契约](simple-kaos.md)，不再默认枚举全部目标对。

本文件用于规范化、关系判断和组装；纯导出不需要加载全部建模规则。例子均为合成示例。

## 规范化

- “及时看到队友修改”与“队友更改后立刻看到更新”可能是同义目标，须先核对主体、对象和条件再合并，保留所有候选与证据映射。
- “白天及时收到消息”与“夜间不接收通知”条件不同，不合并为无条件通知目标，也不机械判矛盾。
- “查看预报”和“根据天气安排出行”可能分别为动作与结果；不能仅凭动作化措辞决定分类，也不能把动作一律提升为目标。
- 拆分复合目标时各部分均需有依据；保留原候选到多个新目标的映射。合并时保留限定条件，而非把证据并集当作对更强表述的支持。
- 目标文本、主体、条件或来源集合变化后标记证据需复核；仅排版变化可复用已有支持，但要记录确属非语义变化的依据。

normalize 的独立产物应包含规范目标、candidate_goal_mapping、排除/诊断记录和 needs_retrace 清单，不自动生成全部目标对。

## 关系

| 标签 | 使用条件 | 输出 |
|---|---|---|
| refinement | 子目标是父目标有依据的范围或情境具体化等，且解释充分 | 父子方向、interpretation、依据、适用条件 |
| related | 有材料支持其联系，但不足以认定精化或等价 | 对称联系与理由，不作为层级边 |
| equivalent | 当前粒度下语义和情境等价，建议归并 | 待审建议；合并需新版本与复检 |
| none | 在声明的材料与评估口径内未建立可采用关系 | 决策记录，不入图 |
| uncertain | 资料不足或多种解释无法裁决 | 不确定原因和人工问题，不当作负例 |

“联系员工”可能帮助“获得内推”，有用或因果关联不自动等于精化。父目标的适用范围与子目标不同、或依赖额外设计假设时，说明条件；不能为了连成图而补边。

首版为当前冻结的 n 个节点枚举 n(n−1)/2 个无序对，同一对只记录一条主要判断。refinement 额外声明 parent_id/child_id，不靠无序对顺序表达方向。若同一对有多种候选解释，保留 alternatives 和待审状态，不用重复边冒充多次确认。

改过节点集合的版本重新计算应评估对集；保留未受影响判断的复用依据。等价归并不能发生在导出时。未来采用关系候选筛选必须记录未评估对与筛选范围，未评估不等于 none。

relate 独立产物为 pair_decisions、候选 edges、评估范围与不确定项。目标缺失时不按参考答案补节点，先记录输入不足。

## 组装与交接

源文只保留一份，模型通过 source_id/evidence_id 引用。大模型上下文优先包含相关目标、证据及相邻片段；需要解释否定、主体或条件时才扩展上下文，不能将截断片段当作完整证据。

验证与修复由 model-review 阶段负责，构建只消费其真实结果。任何修复导致源文、目标语义或端点变化，都使相关追溯/关系/检查结果需要重新核对。没有该阶段实现时明确未检查，仍可输出可审阅草案。
