# Skill 结构与内容优化方案（依据模型比对与概念专项复核修订）

初稿：2026-10-22；本次修订：2026-10-23。

本文为经 Codex 对照现行契约、首轮比对及专项复核后整理的实施方案。本次更新方案文档；skill 合并、脚本迁移、契约扩展及新版生成验证均尚未实施。文中的“确定”表示本方案选定的实施决策，不表示目标已经获得用户采纳、独立评审或形式证明。

## 一、确定的方向、依据与工作范围

### 1. 确定的实施决策

- 将 goal-extraction 与 goal-tracing 合并，保留 goal-extraction 名称，职责为“目标提取与证据核验”；与 goal-model-building、model-review 组成三项正式 skill。
- 合并入口，保留提取与核验的分阶段记录、仅核验能力及原始版本，不把两阶段自检当作独立评审。
- 优先纠正语义强度、意图与信念混淆、推断未标清和维持目标过滤过度，再改善精化及辅助关系表达。
- 目标清单仍以目标为主体；仅对影响目标判断、取舍、精化或未决问题的信息增加必要记录，不恢复逐句分类的庞大诊断清单。
- 先保留现行核心契约，必要的辅助记录单独定义、绑定并验证；改变核心字段或读取语义时再显式升级契约。
- 新版结果写入新运行目录，用相同源文和事先确定的评审口径比较。历史 output 保留为比较材料。

### 2. 证据范围与解释边界

首轮比较覆盖 output 中34篇、398个目标，旧模型包含342条 related、5条 refinement 边，使用 goalforge-model-draft-1。现行建模 skill 使用 goalforge-kaos-1，两者不是同一版本。原生成模型、预算、skill 修订及实际加载路径缺少记录时记 unknown，不能把旧产物的问题直接归因于当前某条规则。

2026-10-23专项复核扫描了398个目标的字段结构，并定向核对13篇中的26个目标及5个诊断项。发现表述强化、来源模态偏差、建模角色不明确和候选遗漏风险，也保留了正确判断及边界案例。31例不是随机样本，不能据此计算整批错误率；诊断项中的候选遗漏也不能直接计为已确认漏提。

本方案依据以下材料，具体证据与判断保留在原报告：

- [首轮结果比对](../runs/codex-comparison-2026-10-22/summary.md)。
- [目标、障碍与偏好专项复核](15-目标障碍与偏好专项复核.md)及[逐例源文](../runs/goal-concept-review-2026-10-23/case-evidence.md)。

- 现行四项 skill 的入口、契约、语义判断规则、工具调用及测试。

PPT采用范围如下。课件含KAOS、NFR、i*等多种方法，应区分方法来源，不把所有关系统一解释为KAOS精化。

| PPT内容 | 采用方式 | 边界 |
|---|---|---|
| 第5—6页：模型支持获取、分析、验证和管理 | 建模发现缺口后回查资料，形成有指向的问题 | 不为资料不足补造需求 |

| 第27、31—32、39页：场景及待定问题 | 用正常、异常场景检查条件、缺口与可能反例 | 模型构造的场景标为分析假设，不冒充访谈事实 |

### 3. 本轮实施范围

本方案包含：入口合并、必要参考规则、支持判断、跨阶段信息保留、兼容迁移、必要工具与展示适配，以及工程和语义回归。

本方案暂不包含：完整形式化KAOS推理器、概率障碍树、自动优化偏好求解器、全量本体分类、重新实现论文流水线、无关界面重做或安装环境改造。遇到材料缺口时保留未知与影响范围，不通过扩大产品范围填补。

## 二、内容边界：什么进入目标，什么作为关联信息

### 1. 内容角色不是整段话的互斥分类

分类针对语义成分。同一段话可以包含目标、障碍、偏好、事实和策略，按需要拆开并保留共同来源。分类只用于改变判断或帮助后续建模，不作为必须逐句完成的工作。

| 内容 | 进入目标清单的条件 | 关联信息如何保留 | 不允许的推导 |
|---|---|---|---|
| 目标 | 对达到、维持、避免或改善某状态有明确意图，或有正面依据支持合理推断 | 主体、条件、范围、原文及必要推断 | 为画树补根；把所有负面措辞排除 |
| 障碍候选 | 困难本身不作目标；如推导补救目标，应另建有依据的目标候选 | 描述困难、可能阻碍的目标、发生情境和判断依据 | 把抱怨直接当已证明障碍；把问题取反当唯一解决办法 |
| 偏好 | 如同时表达期望结果，可保留相应目标；仅口味背景不自动生成需求 | 偏好对象、比较方向或所偏好状态、适用情境、例外 | prefer变必须；个人偏好变全体默认；编造比较对象和权重 |
| 现有能力/事实 | 需有使用目的、继续维持的意图或其他推断依据，才能支持目标 | 标明为受访者报告的现状，必要时保留时间与范围 | 现有能力自动等于明确需求；已实现就没有目标资格 |
| 信念/猜测 | 可支持顾虑及目标推断，但信念内容本身不能直接变要求 | 保留“认为、猜测、不确定”及所述后果 | I think变已知事实；架构猜测变唯一设计 |
| 动作/策略/方案 | 有结果意图时提取结果；具体方式由原文选定时也保留方式约束 | 作为操作化信息、备选方案或涉众策略 | 为追求抽象删掉已明确选定的方式；把习惯升级为强制流程 |
| 提议 | 涉众明确提出的期望可作为候选，保留建议强度；仅采访者提出且未获回应时不算涉众目标 | 标明提出者、条件与采纳未知；模型提出的建议单独标识 | “可以考虑”变已承诺；把分析者建议冒充受访者要求 |

障碍记录首先服务于具体目标：能够合理关联时附目标及依据，不能确定时记录待关联问题，不伪造端点。形式化障碍还涉及领域可发生性与阻碍条件，本轮概念层分析不宣称完成证明。

### 2. 必须分开的判断维度

以下是概念边界，不要求为每个目标强制增加同名字段；优先用现有字段表达，缺失信息保持未知。

| 维度 | 回答的问题 | 记录原则 |
|---|---|---|
| 来源 explicit/inferred | 目标是明确表达还是经过推断？ | 没有“希望”一词也可能明确表达意图；不能按关键词决定 |
| 支持 direct/inferred/insufficient/contradicted | 当前证据是否支持当前整句？ | 按完整含义判断；证据位置正确不代表语义支持 |
| 语气与强度 | 更喜欢、通常、建议、必须，具体是哪一种？ | 保留原句可让步性和例外；不从强度推算人工认可 |
| 采纳与审核状态 | 哪些内容已由谁确认？ | 默认沿用pending；已有真实分项反馈按版本保存，不自动全局认可 |
| 优先顺序 | 哪个目标或方案更受偏好？ | 排名不等于必须/可选，不等于精化或冲突 |
| 满足标准 | 如何判断实现或改善？ | 有阈值保留，无阈值不编造；软目标也可以是有效目标 |

origin与support不必机械相等：一个明确提出的候选也可能因整句扩展或相反证据而支持不足。审核发现不一致时说明原因，不能为凑齐标签改写判断。

### 3. 正反边界样例

| 情况 | 本方案要求 |
|---|---|
| 可接受红眼航班，但更希望睡好觉 | 保留休息目标及非红眼偏好，不产生一律排除红眼的规则 |
| 不希望重要邮件误入垃圾箱，宁可多收垃圾邮件 | 保留Avoid目标、误分类障碍候选和取舍偏好 |
| 缺少环境音就觉得产品不完整 | 审查维持环境音能力的意图；可补充已有目标，避免重复造节点 |
| 只是描述断网可看缓存帖子 | 保存现状；进一步提出维持目标需说明意图或推断依据 |
| 只说喜欢K-pop/R&B | 保留口味背景，不推出排他曲库要求 |
| 先抱怨小窗口难导航，继而提出可考虑改善 | 保留改善目标候选和建议强度，不因包含抱怨而一律降为推断 |

样例用于说明判断边界。正式skill中的示例宜采用少量泛化表达；具体DOC编号、评审答案和论文对应结果留在开发回归材料，不进入生成时的参考包。

## 三、三项skill的职责与合并方式

### 1. 职责与修改权限

| Skill | 输入与交付 | 可负责修改的内容 | 回退边界 |
|---|---|---|---|
| goal-extraction（合并后） | 原文/已有目标/反馈；交付目标、源文映射、支持判断与必要关联信息 | 默认或修订模式可修改目标及支持记录，保留修订前版本与ID映射 | 缺来源或意图依据时给出未决问题；不判精化成立 |
| goal-model-building | 当前已核验目标、支持记录及关联信息；交付模型和精化判断 | 目标组织、精化组和辅助关系解释 | 新增、拆合或实质改写目标须返回提取核验阶段；可由同一助手连续执行 |
| model-review | 当前模型、证据、判断、实际反馈；交付问题与受影响对象 | 审核结论、问题状态和真实反馈处置 | 不静默改目标、删除疑点或替用户采纳；必要时驱动前两项修订 |

主体与责任分别判断：某人表达目标不等于该人承担实现责任。责任未知时不随意分配给软件。

### 2. 合并后的调用模式

| 模式 | 行为 | 修改边界 |
|---|---|---|
| 默认提取与核验 | 识别候选，回查上下文，核验完整语义，必要时修订并重核 | 可修改本次生成的候选，保留前后版本及原因 |
| 仅核验 | 接收已有目标和源文，输出支持范围、缺口及修改建议 | 保留输入目标原件；不自动进入修订模式 |
| 反馈修订 | 按已给出的修改任务或真实反馈修订受影响目标，再核验并通知建模 | 不把无关目标重做；保留未解决问题和反馈范围 |
| 用户明确要求只提取 | 交付目标候选与资料范围，说明支持核验尚未执行 | 不把未核验内容标成已支持或直接送入成立精化 |

默认模式可以连续完成无需再次请求例行确认。只有缺失信息确实决定含义且无法从材料解决时才提出必要问题；提问不等于已得到回答。

内部工作顺序为：识别意图及相关信息 → 建立候选 → 搜索支持、条件与相反证据 → 判断支持范围 → 必要修订 → 重核受影响内容 → 交付。它是职责顺序，不要求每次重新读取全部资料。

有新证据或修订能解决具体问题时继续；无新证据、连续重复同一未决判断或受限于原文时停止该问题的循环，记录原因。其他可完成的目标继续处理。

## 四、内容规则的具体修改

### 1. goal-extraction：提取阶段

将现行“动作、偏好、规则和困难作为必要依据、条件或问题”的规则补充为：

> 目标清单只列有明确意图或合理推断依据的目标。动作、偏好、规则、现状和困难按其作用保留为依据、条件、关联信息或问题；同一句也可能支持目标，不能仅因出现这些内容就排除。只对影响判断的信息建立必要记录。

同时补齐以下决策：

- 从结果意图判断目标，允许达到、维持、避免与优化；对“已有能力”“喜欢现有能力”“不可或缺能力”分别审查。
- 从困难推导目标时区分受阻目的、症状和补救方案；困难解除可能有多种方式，不替用户选择唯一实现。
- 对复合目标逐项检查。混合明确与推断内容时优先拆开或保留分项依据；仍作为一项交付且核心内容依赖推断时，整体不得仅用direct掩盖该部分。
- 合并前核对主体、情境和抽象层次；同义重复可合并，目的与手段不能只因文字相近而合并。拆分不是为了增加数量。
- 核对标题与context，避免标题增加“默认、必须、永不”等强度而把例外藏进上下文。
- 提供排除或保留理由的对象限于争议、高风险或影响覆盖的内容，不对每个普通句子增加诊断。

### 2. goal-extraction：证据核验阶段

保留原goal-tracing的定位、版本和支持判断能力，强化完整语义核对：

- 分别核验位置、识别可靠性、来源版本与语义支持；精确命中只证明位置。
- 读取足以判断意图的上下文，尤其是问题、回答、后续解释和例外。明确表述不要求逐字出现标准目标句式。
- 检查个人习惯到产品默认、偏好到强制、信念到事实、问题到唯一方案、现状到维持要求的跨越。
- 对合理推断写明依据和必要假设；没有正面依据时保留insufficient，不把它包装为inferred。
- 对混合支持列出supported_parts与unsupported_parts。可修订时收窄表述并重新核验；仅核验模式只给建议。
- 支持不足或相反证据未解决的项保留为候选/问题，不作为已支持的精化前提。影响范围局部化，不因此宣称整篇资料不可用。
- 目标或关键上下文、依据变化后更新版本并重判。只变文件格式也应重新建立合法绑定，不能盲目补哈希复用旧包。

### 3. goal-model-building

采用“目标组织—提出精化候选—整组核验—场景检查”的过程：

1. 回答Why、希望达到的状态、适用条件及How，分清涉众目的、系统结果与实现策略。
2. 保留多根、共享和孤立目标。缺少层级的原因可为依据不足、已经足够具体或存在未决选择，不按固定层数补图。
3. AND组在明确假设下共同足以满足父目标；同一父目标的每个OR方案都须单独达到完整性要求。部分贡献、主题相近或操作先后不构成精化证明。
4. 保留障碍候选及目标关联，补救目标作为目标参与建模；仅列出障碍不等于模型已完成风险分析。
5. 偏好表达方案/目标取舍。更喜欢A不证明A足以实现父目标，也不证明A与B逻辑冲突。
6. 将贡献、冲突、操作化、责任与障碍/偏好记录同精化区分。负贡献不自动等于逻辑冲突；主体不自动等于责任方。
7. 以原文场景及明确标识的分析假设检查正常与异常情境，形成具体缺口或反例。发现需要新增目标时返回提取核验阶段。

默认图继续采用目标与精化组的DAG。障碍和偏好优先在相关目标/组的详情与问题中呈现，不把它们伪装成普通目标节点或父子边；是否增加独立图层留待真实使用需求。精化图与辅助关系分别核验，不能统一施加相同的无环规则。

### 4. model-review

工程检查与语义检查分别记录。语义复核按以下问题分类，允许同一对象有多个问题，不将它们混为一个“错误数”：

| 类别 | 判断重点 | 处理 |
|---|---|---|
| 语义偏差 | 范围、强度、条件、主体或选定方案被改错 | 指出具体不受支持部分，建议收窄/修订 |
| 来源与推断偏差 | 信念变事实，现状变明确要求，推断链缺失 | 保留合理意图，重判来源及支持范围 |
| 表达不足 | 含义基本忠实，但障碍关联、偏好或状态未明确 | 补关联信息，不自动计为语义错误 |
| 候选遗漏风险 | 可能因偏好标签或已实现状态过滤掉维持意图 | 回查完整上下文与既有目标覆盖；未确认前不计真实漏提 |
| 精化问题 | 共同充分性、方案完整性、条件、假设或关系角色错误 | 重评对应组，部分组保持候选 |
| 正确/边界案例 | 避免型目标、软目标或有条件偏好被误删的风险 | 明确保留理由、成立范围及未知项 |

优先复核全部精化组、争议关系及影响含义的问题，再按记录的抽样范围检查其他对象。阻塞范围应落到受影响目标或组；只有文件完整性、版本或全局解释无法保证时才阻塞整份交付。

脚本检查、生成方自检、后验语义评审、独立语义审查、形式证明及人工决定分别报告。没有实际执行的项保持not_run；另开一次调用不天然独立。

| goalforge-semantic-judgments-1 | 保留完整语义判断及输入绑定，不让辅助分类替代support |
| goalforge-tracing-draft-1 | 保留定位与支持记录，可在入口合并后继续单独产出 |
| goalforge-kaos-1及对应判断/检查契约 | 精化组与目标语义不变；辅助信息不得混入精化边 |

现行提取契约明确“不加入专业分类字段”。因此本轮不直接向每个candidate塞入kind、hard/soft、mandatory等字段。出现跨阶段的语义缺口时用单独、有契约的辅助记录承接，不能在不声明版本的情况下修改核心含义。

### 2. 最小辅助记录方案

确定采用“按需产生的语义关联附件”，暂用文件名semantic-context.json。以下是实施要求，不代表该文件已经存在或现行工具已支持：

- 只有需要跨阶段保留的障碍、偏好、信念/现状、策略或争议处置才产生记录。一个普通目标的条件已经充分写在context中时不重复复制。
- 每条记录须有稳定ID、语义角色、简短表述、原文引用、涉及的目标/候选ID（允许暂缺并注明原因）、判断依据及必要条件。状态区分材料陈述、分析候选与待确认，不冒充人工接受。
- 障碍记录增加受阻目的及关系依据；偏好记录增加偏好对象/方向和例外。原文没有排名、权重或阈值时不填造。
- 记录事实与信念时保存不确定性，不因进入JSON就变成已验证领域公理。
- 附件必须绑定源文与目标输入版本；建模保存candidate到goal的映射和实际消费的附件哈希。新增判断若依赖该附件，其绑定也必须覆盖附件。
- 修改附件中影响含义的内容，须重评受影响目标/组并重新生成检查与交付；不能把它当不影响语义的自由备注。
- 核心目标的关键限制仍写入目标条件/context，不仅藏在附件；展示须能从目标/组定位相关记录和待确认问题。
- 没有附件的旧输入须仍可处理，但“没有记录”不等于已经排除所有障碍或偏好。

实施时先定义附件的唯一契约与版本，再修改读写、绑定、验证和展示。若现有模型无法完整表达附件依赖或引用，届时升级相关契约并提供旧版适配；不能宣称维持旧版本即可无损支持新语义。

### 3. 用户交付边界

默认交付仍是可审核目标图、JSON与短说明。分类、证据细节及推断按需展开；用户直接看到的是目标、适用条件、关键取舍和需要决定的问题。禁止增加无助于判断的专业字段表或要求用户逐条审核所有中间记录。

问题具有稳定标识、对象引用、证据及状态。后续阶段说明其已解决、仍未解决或不适用的理由；不因进入最终模型就自动消失。

### 2. 工具与调用者迁移

当前kaos_model.py直接从goal-tracing/scripts导入trace_candidates，建模工具文档及测试也引用旧路径。因此“入口合并完成”不等于“三项skill已可独立安装”。

迁移按依赖顺序实施：

1. 盘点CLI、Python导入、模板、参考链接、测试和安装文档中的旧引用。
2. 将追溯工具及所需规则迁入goal-extraction，保留CLI的仅核验能力，更新建模导入及命令示例。
3. 过渡期旧路径可保留转接入口/包装器，调用唯一实现，不保留第二份可分叉语义逻辑；转接目标不可用时明确报错，避免循环调用。
4. 更新README、docs/05、docs/07、docs/10中实际受影响的流程、输入输出及安装说明，安装位置遵循已有用户环境，不自动改写无关配置。
5. 在只有三项正式skill的隔离副本中验证完整流程；另验证约定支持的旧命令。两者分别记录结果。
6. 只有调用者迁移和三项独立安装验证完成后，才将旧goal-tracing入口归档到非发现位置或移除。历史运行附件保留。

迁移不要求统一所有脚本文件名或重写所有旧工具；只修改实际依赖。默认保留既有发现与调用策略，不自行改变为仅显式调用。

## 七、分阶段实施与退出条件

| 阶段 | 工作 | 完成依据 |
|---|---|---|
| A：冻结与基线 | 固定当前四项skill、源文、现有产物和运行环境记录；确定开发案例与评分口径 | 可追溯输入清单；旧draft与现行KAOS基线分开 |
| B：结构合并 | 合并入口、迁移依赖、保留语义规则和原契约，验证各模式 | 三项副本可运行；旧兼容范围明确；改写触发重核 |
| C：语义边界修订 | 实现本方案的目标/障碍/偏好及来源强度规则，加入反例回归 | 已知强化问题得到修正，正确目标与条件未被误删；争议仍可表达 |
| D：跨阶段保留 | 实现必要辅助附件、绑定、目标映射、展示及反馈传播 | 语义记录能进入最终交付；变更使旧判断失效；旧输入仍可处理 |

这里的“发布记录”指本地可交付版本及加载说明；外部发布或额外服务操作不在本方案内。出现版本不匹配、工具不能承接新语义或严重退化时，停止进入下一阶段，修复当前阶段或明确缩小可用范围；已完成材料仍保存。

## 八、验证口径与验收

### 1. 工程验证

复用并调整现有goal extraction、goal tracing、KAOS、review与feedback相关测试。仅在新增契约或行为需要时增加有意义的测试，不写只匹配措辞或标题的测试。

必须覆盖：源文/引文切片、版本与哈希绑定、唯一ID及引用、仅核验不修改输入、目标修订使旧支持包失效、辅助信息变更的影响传播、三项安装、旧命令兼容范围、部分反馈及未决问题保留。修改的脚本实际运行；skill结构校验仅证明入口和资源结构合法，不证明语义正确。

### 2. 语义回归与保护案例

| 回归重点 | 通过条件 | 需要同时保护的情况 |
|---|---|---|
| 红眼航班/通知默认值 | 不增加无依据禁用或默认规则 | 保留原有休息与少打扰意图 |
| 位置缓存/取消评分信念 | 不把猜测记成已知事实或选定方案 | 保留隐私与评分关切 |
| 断连/信息流停载 | 说明从困难推导目标的依据，保留障碍线索 | 合理目标不被一律删除 |
| 环境音/睡眠定时器 | 检查维持意图和已有覆盖，保留必要候选 | 不把所有现有功能自动升级成必须需求 |
| 重要邮件/偶发宕机 | 保留Avoid目标及容忍度 | 不按负面措辞判成纯障碍，不改成零故障 |
| 时间与价格/配色/优先级 | 保留情境、例外和备选关系 | 不强制排序外推、不把低优先级当非目标 |
| 搜索精度/小窗口改善 | 结合完整话语判断直接意图与建议强度 | 不要求出现固定关键词才算explicit |
| 精化与反馈 | 组的完整性有解释，问题和语义变化可追溯 | 不通过增加节点/边或隐藏未决项制造改进 |

这些是语义不变量，允许不同但有依据的表述；不是要求模型复述预设答案。回归中的候选或争议项允许保持未知，不能为通过测试强行采纳。

### 3. 比较设计与指标

- 保留DOC010、DOC023、DOC031作为已接触开发案例，加入本次正反边界案例，并选择其他不同长度和复杂度文档作扩展回归。它们仍不能冒充未见测试。
- 若需要区分合并收益与规则收益，使用同一当前基线重跑三个版本：原四项流程、仅结构合并、合并后内容优化。历史旧draft产物另作回顾参照，不将跨schema变化全归因于合并。

- 分开统计已证实表述偏差、来源/推断问题、表达不足、候选遗漏风险、有效目标覆盖、精化质量与未决项。分母、文档范围和无法判断项须明确；不将候选遗漏直接计漏提，也不合成任意加权总分。
- 已知语义强化和信念升级问题应不再出现；正确反例须保留有效含义；任何新增严重偏差须修复或记录为阻止该版本通过的退化。整体改善结论以实际复核为准。
- 位置和工程检查、自动语义评审、独立验证分别报告。若后续实际执行新上下文或独立评审，记录其可见材料与范围，不提前标为完成。

验收不以目标数、边数、深度或连通率增加为成功。精化不能成立时，准确保留独立目标与问题也可以是正确结果。
