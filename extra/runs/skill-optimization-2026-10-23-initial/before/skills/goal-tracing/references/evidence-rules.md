# 证据口径与边界示例

本文件示例为合成案例，不属于正式标注。

## 忠实接入

优先复用目标提取阶段的转换稿与源索引；已有标准全文保持不变。原始材料需要转换时保留原件，另存 UTF-8 LF 文本及片段到原件的映射，不先摘要。Word 保留段落/表格顺序，PPT 保留幻灯片及语义图形关系，录音保留可核实时间段和说话者未知状态；实际工具不可用时报告限制，不假装完成读取或转写。

引用位置分两层：转换稿的 Unicode 码点半开区间，以及原件的页码、段落、幻灯片或时间段。原件无法确定页码时不猜测。不得把转写稿字符位置称为录音中的时间定位。

## 定位与版本

只有实际可读的标准全文能够产生经过验证的全文偏移。只获得片段文本时可以验证片段匹配，但全文偏移为 null，并注明 verification_scope=segment。exact 表示在声明的核验范围内精确匹配，不暗示已核验整个原件。

重复引文先使用 source_id 限定，再使用说话者和上下文消歧；同一片段多次出现时保留所有候选位置，无法区分则 ambiguous。不得用第一次 find 命中替代消歧。

大小写、标点、编码异常或拼写修正导致不匹配时，submitted_evidence 保留 not_found；可另提原文中的 located_evidence，说明更换原因，不将近似匹配记作精确匹配。多段原文分别引用，不能省略号拼接后当成连续引文。

全文哈希不符时对应文本记 version_mismatch，不沿用不匹配偏移。来源变更后重新定位，记录版本关系并保留已执行的证据结果。

## 支持判断示例

| 目标 | 原资料 | 结果及理由 |
|---|---|---|
| 搜索结果两秒内返回 | 用户说“搜索结果应在两秒内返回” | direct，主体、对象、阈值一致 |
| 搜索结果两秒内返回 | 用户说“希望搜索快一点” | insufficient，只支持速度诉求，不支持两秒阈值 |
| 降低使用费用 | 用户抱怨费用太高并因此改用其他方法 | inferred，说明减少费用的推断及假设 |
| 夜间推送提醒 | 用户说“夜间不要推送提醒” | contradicted，适用情境一致而关键含义相反 |
| 白天推送提醒 | 用户说“夜间不要推送提醒” | insufficient，没有说明白天应如何处理 |
| 自动发送日报 | 采访者问“要自动发吗”，受访者未回答 | insufficient，未确认采纳 |
| 重要决定正式留档 | 文档中明确要求“重要决定须通过邮件留档” | direct，方式与主体信息仍需保存 |
| 夜间不要通知 | 转写稿关键“不要”无法听清 | insufficient，不能忽略识别歧义 |

inferred 不是比 insufficient 更礼貌的说法：前者须有正面的推断依据，后者是资料不足以支持目标当前表述。可建议更保守的表述，但不直接修改输入目标。

## 相反与冲突证据

可存在多条 supporting 或 opposing 证据。先比较主体、时间和情境，不将不同条件下的要求判成矛盾。同一条件下明确相反且没有有效支持时为 contradicted；混合冲突无法决定时为 insufficient 并提出人工问题。

模型只报告“本次实际搜索范围内未找到”，不声称未读取或不可用原件中绝无证据。文件夹可读不等于这些文件都属于授权证据范围。
