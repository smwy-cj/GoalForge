# 目标清单

请核对目标是否符合原意；需要时在统一意见区说明。

材料：DOC021.txt

1. 搬到新街区或新国家时，找到可租的新住处。
   条件：自述唯一触发情境：迁居；手段为搜索网络与房源类网页应用
2. 找到目标地区最主流、当地人最常用的房源平台。
   条件：理由：可能是在另一个国家，不知道当地用哪个站
3. 选到合适的街区：预算与需求集中、靠近工作或学校、有本地人推荐。
   条件：三条依据：平台上房源聚集、熟人推荐、通勤/就学距离
4. 先用硬条件（面积、卧室数、租金上限）圈定候选，再用软条件（设施、观感）细化。
   条件：自述筛选顺序：size/bedroom/budget → amenities/looks
5. 通过对方的回复速度与信息完整度判断房源与房东是否可靠，据此缩小候选。
   条件：回复快且信息全 → 加分；回复慢、信息少、态度可疑 → 减分
6. 知道房源信息最后更新时间，避免依据过期信息做判断。
   条件：现状：详情页无更新时间；后果：可能是过期或错误信息，不敢信
7. 清楚知道发出联系后会经历什么、多久有回应。
   条件：参照电商的配送预期；自己提出用时间线/流程图展示后续步骤
8. 表达意向时不必提交全部个人信息与精确需求。
   条件：表单把姓名、邮箱、手机、入住日、卧室数、浴室数、留言全设为必填；他常在填表前就放弃并绕开流程
9. 像电商加购一样，直接对某个具体房源一键表达意向。
   条件：理由：房源是有限选项，不是定制品，无需长表单描述需求
10. 不注册、不登录也能直接搜索和浏览全部功能。
   条件：理由：看房不需要账号，也没有需要个性化的内容；可接受：想保存信息时再选择性注册
11. 能在地图上画圈选区，而不只按街区名检索。
   条件：理由：按街区名太死，边界外两百米的合适房源会被漏掉
12. 看到真实住户的评价，用来判断房源与房东是否可信。
   条件：评价被他列为「喜欢」的两件事之一；详情页确实会带住户评价
13. 收藏的房源能在导航栏或一级菜单里找到。
   条件：现状：点了收藏但找不到存到哪里，菜单里没有入口
14. 把三四个候选房源放在同一屏里对比主要条件。
   条件：自述「没找到有网站做这个」；结尾再次强调这是他最想补的功能
15. 筛选时可以自行选择是否纳入「未填写该条件」的房源，避免误筛掉。
   条件：担心：房东没勾选「可养宠」但实际允许，一筛就漏；方案：加一个 include unspecified 复选框
16. 房源照片有统一拍摄规范，避免过度美化或敷衍。
   条件：现状：有人拍得很随便、有人刻意拍得比实景好；设想：规定采光与角度
17. 所有租房沟通都在同一个平台内完成。
   条件：现状：几乎全部沟通都转到平台外（邮件、电话、地图找官网）；原因：站内流程不透明、按钮含义不明
