# 新版 Skills 优化效果评估方案

日期：2026-11-02。状态：方案建议，尚未执行新一轮实验。

## 1. 评估目标与已有证据

本次评估回答三个问题：

1. **相对旧版是否改善？** 分别评价目标覆盖、语义忠实性、关系质量、精化质量与使用成本。
2. **是否缓解论文指出的问题？** 为每项局限建立对应测试，区分已缓解、未改善、能力未覆盖和证据不足。
3. **改善来自哪里、幅度多大？** 控制生成模型与预算，区分技能整体效果、具体机制效果和额外计算投入。

现有八篇、两轮开发比较已经提供了积极信号：

| 指标 | 第一次运行：旧→新 | 第二次运行：旧→新 |
|---|---:|---:|
| 冻结的129条意图完整对应数 | 97→110 | 95→114 |
| 清单完整对应比例 | 75.19%→85.27% | 73.64%→88.37% |
| 比例变化 | +10.08个百分点 | +14.73个百分点 |
| 建议修改目标数 | 10→4 | 6→0 |
| 独立联系数 | 0→117 | 0→76 |
| 成立精化组数 | 0→0 | 0→0 |

以上依据[冻结比较指标](../runs/skill-optimization-2026-10-25-complete/evaluation/metrics.json)重新汇总。清单及判断由模型编制，数据已用于开发，预算未严格控制，最终规则又在评估后补充。因此目前可以说“实验快照在这些开发案例上承接了更多意图”，尚不能证明最终新版的普遍效果。独立联系数量增加体现表达能力扩展；是否准确需逐项评价。零成立组也无法证明精化识别能力提高。

下表中“论文依据”是对原文的简要归纳；“实验设计”为本方案提出的方法。论文已发现移动窗口对提取位置分布有帮助，评估重点应进一步检查新版全篇校正和语义整理的增益。

| 编号 | 论文依据 | 新版对应机制与能力边界 | 本次测试 |
|---|---|---|---|
| L1 | VI-A：混合语义簇随机取代表会丢失不同目标 | 语义拆合、候选去向记录 | 固定候选集合，测整理后的有效意图损失与重复 |
| L2 | VI-B/C：背景或偏好被误作目标，人工目标也可能缺少原文依据 | 目标资格、完整语义支持和推断标记 | 正反边界案例及真实源文双向审核 |
| L3 | VI-D：整篇提取存在靠前偏差，移动窗口分布更均衡 | 分窗捕获后核对全文 | 按真实意图所在位置和跨轮距离测覆盖 |
| L4 | VI-E：关系遗漏、方向颠倒及互补目标误连 | 类型化联系、方向检查、精化组分开判断 | 固定目标集评关系发现与方向；重复运行评稳定性 |
| L5 | VII：未涵盖 AND 精化 | 支持共同充分组及完整替代组，语义效果待证 | 正例、缺项、反例及替代方案测试 |
| L6 | VII：未评估可观察性、可控制性及目标超出系统影响范围的问题 | 当前没有完整责任分配或形式化验证能力 | 专家标注可观察性、控制边界及范围，核查系统是否过度承诺 |
| L7 | VII：学生访谈与单一模型限制外部效度 | 技能结构本身不能消除这类限制 | 新来源访谈、跨领域和跨模型验证 |

另将代理、操作、冲突和障碍的完整建模列为能力清单检查；当前技能未完整实现这些扩展。记录相关问题或理由只能证明信息被保留，不能计为对应模型元素已经实现。

## 3. 固定比较版本，分开两条评估轨道

### 3.1 Skills 前后比较：主要实验

| 版本 | 冻结对象 | 回答的问题 |
|---|---|---|
| S0：第一轮修改前四技能 | `extra/runs/skill-optimization-2026-10-23-initial/before/skills` | 当前版本相对第一轮修改前有何累计变化 |
| S1：第二轮修改前三技能 | `extra/runs/skill-optimization-2026-10-25-phase1/before/skills` | 第二轮修改带来多少增益 |
| S2：当前最终三技能 | 本次执行开始时冻结 `skills/` 的实际文件及哈希 | 最终版本的实际效果 |

**S2 对 S1 为主要比较，S2 对 S0 为累计比较，S1 对 S0 为补充比较。** 历史398目标使用更早的二元关系格式；S0快照可能已包含后续KAOS规则，不能称为398目标的精确生成环境。执行前核对快照内部契约，若要复现最初输出，需另找匹配的历史技能及运行配置。

三版本统一模型、源文、任务说明、语言和可用工具。各自按冻结技能执行，不将新版规则补入旧版。适配仅限运行路径和统一评审格式，保留原始输出与转换日志。

### 3.2 论文相关问题：定向测试与可选方法基线

设置两个不同角色：

- **P-artifact：论文公开产物。** 保留1,600目标和公开图作案例、差异及历史错误回查，不视为人工真值，也不作为同模型因果对照。
- **P-method：在当前同一模型上重跑作者方法。** 只有需要支持“优于论文方法”时加入；准确记录提示、窗口、重复次数、整理分支及图生成规则。更换模型后的运行只能称同模型方法比较。

作者正文的聚类取代表与公开代码读取的摘要分支要分别标记，不能混成一个基线。若只重跑其中一种，限定结论到该配置。无法还原关键环节或资源不足时，保留定向测试，结论写为“缓解论文描述的某类问题”。

论文关系与当前严格精化组不使用同一评分表。另设两份标签：A表按论文的二元关系定义，B表按当前四类联系和充分精化组定义。A表可供历史方法比较，B表评价新增能力；禁止把全部新联系一律映射为论文精化边。旧版不支持的类型记录为能力缺口，公共能力比较单列。

## 4. 数据与人工参考答案

### 4.1 三层数据

| 数据层 | 建议范围 | 用途与边界 |
|---|---|---|
| 开发回归 | 现有34篇；先用已有八篇试运行 | 检查改善和退化；全部已接触，不能再称未见测试集 |
| 局限挑战集 | 初步每类问题8—12个不同基础场景，数量可按预算调整 | 控制条件、否定、重复、跨轮指代、关系方向和精化反例；合成案例单独报告 |
| 外部验证 | 新收集12—20篇来自至少3类业务场景的访谈，覆盖不同长度 | 验证迁移；优先纳入专业访谈及多方需求；执行前确认使用范围 |

上述数量是工作量起点，不代表已经满足统计功效。若无法取得新资料，完成前两层仍有价值，但结论限定于开发资料和挑战场景。增加同一文档的重复次数不能代替增加独立文档。

### 4.2 原文优先建立参考答案

由两名具备需求分析知识的评审者独立阅读原文，在查看任何分支结果前编制参考意图，并交叉裁决。评审者不读取论文目标列表补答案。

每条参考意图记录：稳定ID、完整含义、主体、条件、否定、强度、所选方式、证据位置，以及显式/推断/不确定状态。为必要的多目标共同承接保留映射空间，避免将新版粒度偏好直接写成唯一答案。

先用两篇开发资料校准标注手册并冻结，随后开始正式评审。争议保留原始意见及裁决，报告一致率与适用的标注一致性指标。人力不足时可先由隔离模型辅助整理，但最终未获人工裁决的部分明确标为探索性结果。

查看输出后发现参考清单漏项，应由不知分支的裁决者核对原文，形成有版本的勘误，并对所有分支统一重算；同时保留最初冻结清单的结果。

## 5. 实验设计

### 实验A：端到端版本比较

三版本对相同访谈独立完成提取、核验、建模和交付。每篇每版本建议至少3次全新上下文运行，随机交错执行版本，避免时间或服务变化只影响一个分支。

冻结任务提示、模型标识、采样参数、工具权限、轮次及停止规则。生成者只能访问原文、分配的技能与必要工具，不能访问参考答案、历史输出、评价报告或其他分支；仅靠提示声明隔离不够，工作目录和可见文件也要隔离。

第一次提交结果用于主分析；后续修复另存。所有失败、重试、空结果和超预算运行均进入台账。失败运行的端到端覆盖记0，同时报告成功运行条件下的质量和整体成功率；无法解析的结果不能只从分母中删除。

预算分两个角度报告：

- **相同总预算上限下的效果：** 每篇三版本使用相同总token/费用上限，包含内部补查和重试；提前完成不强迫耗尽预算。
- **各版本按完整流程运行的效果与成本：** 作为补充，报告自然工作量差异，避免将额外投入全归于规则收益。

预算值先由开发试运行估计，再在正式评审前固定。若环境无法获得精确模型或token，明确降为配置受限的描述性比较，不能用运行时长冒充等token控制。

### 实验B：固定目标集，单独评建模

选择八篇复杂度不同的开发文档，用同一份人工核验目标及证据作为输入，分别交给S1和S2建模，目标内容完全锁定，每分支重复3次。

对较小目标集评全部有向目标对；较大目标集先定义统一抽样框，覆盖各分支所提联系的并集、人工识别的正例、近义项、互补但无精化的困难负例，以及随机未连目标对。记录抽样概率；非全量且非等概率的结果需加权或只按分层报告，不能直接当总体准确率。

评审类型、方向、证据、条件和状态。直接关系与传递可达关系分别计算。重复稳定性同时报告“每次都正确”和“每次都重复同一错误”，避免把一致性等同于准确性。

成立精化组逐组检查父目标范围、子目标集合、条件和假设。零输出时正确率记“不适用”，继续通过人工正例检验漏检。

### 实验C：逐项检查论文局限

| 对象 | 具体操作 | 关键判据 |
|---|---|---|
| L1 整理损失 | 给各整理方法同一批含同义、同主题异意图、目的/手段的候选及原文；固定候选输入后比较输出 | 候选中原本存在的有效意图保留率、错误合并率、冗余率；追踪损失发生在哪一步 |
| L2 目标资格 | 将投诉、偏好、现有能力、采访者建议与受访者确认组成正反配对 | 既不将背景强行升级，也不丢失有依据的维持/避免意图；条件及支持标签正确 |
| L3 位置与上下文 | 将源文分10段，按各段参考意图计算覆盖；另按跨轮距离分层 | 使用每段真实意图作分母；不能因各段输出数量均匀就判改善 |
| L4 关系错误 | 使用固定目标和困难正负例，交换呈现顺序并重复生成 | 漏检、错连、反向及类型混淆分别减少，不能通过全不连边获得高分 |
| L5 AND精化 | 使用明确共同充分的组、删掉必要子目标的组、带异常反例的组、完整替代组 | 正例识别与负例拒绝同时成立；保持拒判率可见 |
| L6 系统范围 | 人工区分可控制、可观察、外部结果、范围不明 | 未把外部结果伪装为系统保证；无法表达的结构如实记录缺口 |
| L7 外部效度 | 在新来源资料上复做S1/S2；条件允许再加入第二种生成模型 | 每种模型内部比较新旧；不能以“新技能+新模型”对“旧技能+旧模型”归因 |

位置移动仅用于语义不依赖上下文的受控片段，保留完整问答；移动后若含义变化则排除。挑战集各变体归属于同一基础场景，统计时不能作为独立样本。L6中超出直接控制范围的高层目标未必无效，重点评责任边界和实现声明是否准确。

### 实验D：机制消融

在S2上每次移除一个机制，保持其余规则、数据契约和总预算一致：

1. 移除局部分窗候选捕获，保留全文读取及核验。
2. 移除“一目标一核心动作”的明确约束，保留其他资格规则。
3. 移除候选去向记录及覆盖回查，保留必要输入输出结构。

三个变体与完整S2在同样八篇上各重复3次。先检查变体可正常运行，避免把损坏流程当作消融。联系层的表达增益主要由实验B检查，新增类型无法仅靠删字段构成公平对照。

移除机制后的变化只能说明该机制在当前组合中的条件作用；存在机制交互时，不把各项差值相加当作总收益。预算有限时，先完成A、B、C，D用于后续解释来源。

## 6. 指标与评分规则

### 6.1 两个主要终点

**意图完整覆盖率 C = 被完整承接的确定参考意图数 / 确定参考意图总数。**

完整承接要求主体、核心结果、必要条件、否定及所选方式均被保留。允许多个目标共同承接一条意图，但每条参考意图最多计一次。只在解释或关系理由中出现、未进入实际目标内容的要求不计完整承接。部分对应另报，不在主指标中给半分。

**无依据声明率 H = 含至少一项实质无依据内容的确定输出目标数 / 确定输出目标总数。**

另报每篇无依据目标数、每100条参考意图对应的错误数，防止新增大量正确细目标稀释错误比例。待确认候选单列数量和人工判定，不当作已支持目标；将有效意图全部留待确认也不能取得完整覆盖分。空输出的H记不适用，C及失败率照常报告。

主要评价对象为整体意图集合与每条目标的语义支持，目标数量不作为主要终点。不从宽松候选对应推导标准precision/recall/F1；若另做标准集合指标，须先冻结语义等价及拆合的匹配协议。

### 6.2 次要指标

| 维度 | 指标和分母 |
|---|---|
| 条件忠实性 | 主体、否定、时间、数量、强度和方式错误；以适用且已评对象为分母，另报原始数 |
| 粒度 | 多意图混装、无独立意图的过拆、语义重复率；同一对象多问题不重复算错误目标 |
| 证据 | 引文切片匹配率与全文语义支持率分列，原文真实不自动等于语义完整 |
| 联系 | 分类型、分方向的正确率和参考正例检出率；抽样加权、拒判和缺乏类型能力另报 |
| 精化组 | 输出成立组中成立比例、参考正例检出率、反例误通过率；按组而非按二元边计分 |
| 稳定性 | 同一文档多次运行的覆盖、错误和联系方向波动；保留最差运行 |
| 工程 | 首次可交付率、修复后可交付率、哈希与版本绑定、失效判断是否被阻止 |
| 成本 | 每篇总调用/token/耗时/可获得费用、人工复核分钟数；失败及修复都计入 |

人工复核用时需固定任务和评审界面；若使用不同产品界面，则作为端到端使用实验另报，并随机化次序、平衡评审者。未经实际计时不得声称降低人工成本。

### 6.3 评审顺序

先看匿名目标与源文评语义，再看生成方支持标签评状态是否恰当；隐藏分支、生成自评与历史成绩。关系类别保留必要内容，因此只能称去分支标签，不能保证评审者完全猜不出版本。

所有主要终点实行双人独立评价及裁决。次要指标若抽样，事先固定范围和权重。无法裁决的参考意图、目标或联系单列比例，并报告将其作有利/不利判定时的敏感性范围。

## 7. 如何回答“优化效果如何”

以文档为主要统计单位：先汇总每篇各次运行，再计算新旧配对差值和文档宏平均；总体微平均作为补充。置信区间采用按文档成组的配对重采样，挑战集按基础场景成组；多次运行、目标和引文不能作为独立文档扩充样本量。

报告绝对差值、95%置信区间、改善/持平/退化文档数及各类退化实例。小样本区间只作不确定性描述，不能保证检验功效。正式外部验证样本量应根据开发阶段文档差值方差、希望识别的最小改善和可用预算另行确定，并在查看外部结果前锁定。

建议在试运行后、正式结果解盲前确认以下决策标准。数值是项目接受阈值建议，非论文规定或已验证标准：

- 完整覆盖率平均提高至少5个百分点；有足够样本时，其差值区间下界大于0。
- 无依据声明率差值区间上界不超过+2个百分点，同时审查每篇绝对错误数和严重条件错误，防止分母变化掩盖退化。
- 关系发现须同时看正确性与检出率；精化须同时看正例识别与反例拒绝。
- 对“更高效”的结论，必须显示同预算效果或达到同等质量所需成本的改善。若质量提高伴随成本上升，报告实际取舍。

不合成一个任意加权总分。最终按下列方式判定：

| 结果 | 可用结论 |
|---|---|
| 主要收益达到预设阈值，忠实性不劣，外部验证也支持 | 在所测模型、预算和场景下有可重复优化 |
| 某些维度改善，其他维度退化或成本明显增加 | 局部优化，列明代价和适用条件 |
| 均值向好但区间宽，或只有模型评审/开发样本 | 有改善迹象，证据不足 |
| 语义指标基本不变，仅图或格式新增 | 能力扩展，效果收益尚未证实 |
| 关键指标下降 | 存在退化，定位到具体文档与机制 |

论文局限逐项采用同样判据；L6、L7不能靠流程设计或合成样本自动宣布解决。

## 8. 建议执行顺序与工作量

1. **准备与冻结。** 核验S0/S1/S2快照，固定模型、任务、预算规则和标注手册；确认双人评审资源。创建新实验目录，保留全部历史产物。
2. **八篇试运行。** S1/S2各3次，共48次端到端运行。先验证任务和评分可执行，并估计成本；若随后修改了技能或任务配置，这批结果只作试运行，不进入正式主分析。
3. **34篇正式比较。** S0/S1/S2各3次，共306次端到端运行。只有试运行与冻结协议完全一致、且事前允许纳入时，才计入其中48次，余258次。
4. **固定目标建模。** 八篇×S1/S2×3次，共48次建模运行，与端到端生成分开统计。
5. **局限挑战与可选消融。** 按基础场景逐项测；三个消融变体×八篇×3次为72次追加运行，可复用同协议完整S2对照。挑战集按最终场景数另计。
6. **外部验证。** 冻结最终方案后，新资料S1/S2各3次；12—20篇对应72—120次端到端运行。第二模型、论文方法重跑均作为额外预算项。

成本有限时，优先完成“两版本八篇试运行＋双人原文评审＋关系与精化正反测试”。随后扩展34篇，再补外部资料。没有人工评审或新数据时，先交付探索性结论，不将缺失环节默认通过。

## 9. 交付物与最终报告

建议新实验目录使用 `extra/runs/skill-effectiveness-<执行日期>/`，至少保存：

- `protocol.md`：假设、主要终点、版本、预算、停止规则、纳入与排除规则。
- `versions/`：技能快照、文件哈希、工具适配记录。
- `reference/`：原文优先意图、关系与组参考答案、双人标注、裁决和勘误。
- `runs/`：每篇每版本每次原始输出、首次失败、修复副本和实际成本。
- `reviews/`：匿名评审材料与实际判定；分支映射独立保管。
- `results/`：逐文档指标、配对差值、区间、退化案例和各局限结论。

最终报告先回答S2对S1及S0的效果，再逐项回答L1—L7，最后解释机制与成本。每项结论附“指标变化、适用范围、支持证据、剩余问题”。本方案不预设新版一定更优，也不以达到论文目标数量、增加连边或通过工程测试作为语义优化成功标准。
